# Промахи в бою

Для обычного выстрела, удара и укуса используются параметры оригинального
`base/items.cfg` (импорт в `config/weapon_catalog.json`) и восстановленный
расчёт `TSItem.GetAccuracy`, адрес `0xa7ad00` в `silver.dll`.

Ранее сервер всегда использовал базовую точность: например, AK 47 имел 65%
на любой дистанции. Теперь точность AK 47 — 89% на одной клетке, 77% на пяти
и 65% на девяти. Beretta остаётся 70%, Knife — 85%, кулаки — 90%,
Dog Fangs — 85%, Freak Melee Combat — 90%, Freak Hammer — 95% без способностей.

К базовой точности добавляется `accuracy_gain_amount * (1 - t)`, где
`t = (distance - minRange) / (maxRange - minRange)`. Клиент хранит `t` как
Single, затем округляет результат к ближайшему чётному. При одинаковых
границах дальности `t=1`. Старое поле `accuracy_coeff` в этой функции не
используется. Дистанция — существующий округлённый евклидов расчёт клиента.

Восстановлены бонусы `TSActor.GetAccuracyBonus` (`0xa83c38`): способность 10
для ближнего боя, 17 для лёгкого оружия, 18 для собак. Используется значение
изученного ранга из каталога способностей. Итог ограничен 95%.

[Официальное руководство](https://ti.ggeek.ru/files/TIO_manual.pdf), стр. 104,
подтверждает максимальную точность 95%, даже если оружие и бонусы дают 100%.
Стр. 106 отделяет оружейную умелку от точности: она влияет на урон; промахи
тоже развивают умелку, слабее попаданий. Существующий расчёт тренировки сохранён.
Это воспроизведение доступной клиентской формулы. Код генератора случайных
чисел исходного сервера не найден: проверка попадания остаётся равномерным
броском 0–99, а разброс урона — равномерным выбором внутри интервала.

## Дистанция и урон

У обычных атак сначала к обоим концам интервала добавляется заточка, затем
применяется коэффициент `1 - (1 - damage_fade/100) * t`, усечение до целого,
оружейная умелка `(67 + skill) / 120` и ещё одно усечение. Затем сервер
выбирает урон и применяет существующий расчёт брони. Этот порядок восстановлен
из `0xa7a576..0xa7a67f` и `0xa7a826..0xa7a890`.

Для точного совпадения с клиентом сохранено округление промежуточных x87
операций до 64-битной мантиссы: например, Spas на пяти клетках даёт 42–56,
а алгебраическое упрощение формулы ошибочно даёт верхнюю границу 57.

| Оружие | Дальность | Без умелки, заточки и брони: вблизи → вдали |
|---|---|---|
| AK 47 | 1–9 | 50–75 → 37–56 |
| Shotgun | 1–5 | 50–75 → 10–15 |
| Spas | 1–7 | 70–95 → 28–37 |
| AWP | 7–18 | 50–75 → 60–90 |
| Groza | 1–8 | 30–38 → 46–58 |

Руководство, стр. 44–45, описывает преимущество дробовиков в упор и рост
урона дальнобойного оружия с дистанцией. Нельзя распространять один
коэффициент на весь класс: даже Groza и AK 47 имеют разные зависимости.

`normalize_weapon_xml.py` переносит параметры всех 39 оружий в действующие
XML-поля: `value damageFade`, `for/add accuracy`, `for/add accuracyGain`.
Два последних значения задаются долями единицы: нативный читатель умножает
их на 100. Перестроение каталога сохраняет эти привязки.

Особые эффекты пулемётов, RPG, огня и взрывов не подменяются обычным выстрелом.
Ранее не поддерживаемые типы атак остаются отклоняемыми; существующий взрыв
Frag Grenade сохраняет свой отдельный расчёт. Для Minigun-типа восстановлен
этап зависимости урона от дальности с `offset=distance`, но полная серверная
механика очереди по площади здесь не реализуется.

Промах расходует обычную стоимость атаки в AP и боеприпасах. Он не наносит
урон и не считается поглощением бронёй. Попадание с нулевым уроном само по
себе не превращается в промах. Существующие правила взрыва гранаты не менялись.

## Штатное отображение

В `silver.dll` обработчик `0x9602d4` различает результат атаки:

- `0` — обычный результат;
- `2` — промах, ключ локализации `ch01`, русский текст `*Промах*`;
- `4` — критическое повреждение, ключ `ch04`.

При `skill_id=0` клиент читает общий результат пакета `4B` (смещение 35).
Для способности читает результат каждой цели (первая — смещение 47).
Раньше сервер передавал обычный результат с нулевым уроном при промахе.
Теперь оба поля заполняются корректно; массовый удар может попасть по одной
цели и промахнуться по другой. Исправлено также общее поле критического укуса.

Вывод текста остаётся штатным: ветвь `0x960709` выбирает `ch01`, помощник
`0x9601f8` размещает надпись у видимого атакующего, либо у видимой цели.
Локализация не изменяется; параметры оружия устанавливаются штатным механизмом
временного каталога при запуске клиента.

## Проверки

`python tools/verify_miss_native.py` исполняет оригинальные x86 инструкции
выбора результата и размещения текста: 6 сценариев, плюс 3 сравнения пакетов
с оригинальным сериализатором. Результат — `evidence/miss_native.json`.
Локализация, видимость, экранные координаты и очередь рисования в этой проверке
заменены явными заглушками: проверяется вызов вывода, а не изображение на экране.

`python tools/verify_weapon_range_native.py`: привязки XML для 39 оружий,
825 сравнений урона и 275 сравнений точности с оригинальными инструкциями.
Для обычных атак дополнительно проверен переход к урону при умелке 35.
Читатель числового XML-значения, поиск метаданных предмета и флаг noLimit
заменены явными заглушками; сами вычисления выполняет `silver.dll`.
Отдельно выполнены 6 проверок оригинального выбора бонуса способности.
Отчёт — `evidence/weapon_range_native.json`.

Регрессионные тесты проверяют дистанцию, порядок применения умелки,
бонусы способностей, предел 95%, расход при промахе, нулевой урон при
попадании и разные результаты целей массового удара.
Полный запуск `python -m unittest discover -s tests -q`: 480 тестов проходят.
Визуальная проверка подсказок в запущенной игре в этот раз не выполнялась.

Для проверки в игре перезапустить эмулятор и клиент через
`python tools/run_reservation.py`, выполнить несколько выстрелов и ближних
атак. При промахе должна появиться штатная надпись `*Промах*`, AP и патроны
уменьшаются, HP цели остаётся прежним.
