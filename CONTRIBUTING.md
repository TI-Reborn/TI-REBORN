# Работа над изменениями

Разработчик ilyaplot работает в отдельной ветке и открывает pull request в `main`.
Владелец Junduge проверяет и одобряет изменения. CODEOWNERS назначает владельца
для всех файлов; обязательность его review обеспечивается настройками GitHub.

В PR укажите проблему, поведение до/после, затронутые аккаунты/сервисы, команды тестов,
результат, изменения схемы SQLite и порядок отката. Автотесты, TCP-клиенты и настоящие
игровые клиенты — разные уровни проверки; не смешивайте результаты.

Сохраняйте существующие пути и API, пока перенос не выделен в отдельный PR.
Проверяйте авторитетность сервера, транзакции, дубли запросов и reconnect.
Не коммитьте пользовательские данные, журналы, адресные конфиги, ключи, пароли и дампы.
Не добавляйте автоматический deploy в CI и production-секреты в Actions.

Перед PR: `python tools/check_handoff.py`, `python tools/run_server_checks.py`,
тематические тесты. Полный исследовательский suite имеет внешние зависимости;
см. `docs/VALIDATION.md`. Известная ошибка baseline не разрешает игнорировать новую ошибку.

Hosted QA: только зарезервированные случайные логины из `tio/rating_visibility.py`
или явное `rating_exclusions(account TEXT PRIMARY KEY)` до тестирования.
Удаляйте только собственные одноразовые фикстуры. Пользовательский TestClan и обычные
аккаунты не являются тестовым мусором. Хостинг и выпуск доступны владельцу отдельно.
