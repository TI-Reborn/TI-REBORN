# Игроки в локации и чат

Подготовлено локально 22 сентября 2026. На VPS ещё не установлено.

## Что добавлено

- Общий список настоящих подключённых персонажей одной локации. При выходе, переходе в другую локацию и изменении статуса боя список обновляется. Боты в городской список не попадают.
- Штатные сообщения клиента: глобальный, торговля, помощь, личные сообщения; также обработан отдельный канал локации. Русский текст передаётся в UTF-16LE.
- Публичная карточка по нику, в том числе сохранённого персонажа вне сети. В разделе «О себе» показаны размер отряда и сохранённые победы, поражения и ничьи, включая бои с ботами. Запрос не раскрывает пароль, кошелёк или инвентарь и не изменяет сохранение.
- Ограничение чата: 200 символов, 5 сообщений за 5 секунд, ограниченные очереди. Отправитель определяется сервером. Личные сообщения получает только указанный персонаж.
- События `presence_join`, `presence_move`, `presence_leave`, `chat_message` в журнале. Содержимое переписки не добавляется в эти события.

Уровень в списке и заголовке карточки сейчас равен максимальному уровню бойца сохранённого отряда. Исторический онлайн, официальные рейтинги, кланы/альянсы, подробная таблица наёмников в карточке пока не восстановлены; их поля остаются пустыми/нулевыми. Это не означает, что историческая статистика игрока действительно равна нулю. Общие показатели боёв доступны в «О себе» из журнала сохранённых результатов. Старые бои без сохранённого результата восстановить нельзя.

## Руководство и проверка протокола

[Руководство Total Influence, Light Vision Interactive](https://ti.ggeek.ru/files/TIO_manual.pdf), раздел чата, с. 13: различаются каналы локации, торговли, помощи и личная переписка. Боевое общение описано отдельно. Движущиеся городские аватары не требуются для списка присутствия.

Конкретный формат восстановлен из установленного оригинального `silver.dll`, SHA-256 `a73396748ea5c3530157db53592a9f3e04744592c3711f38d40d4877b785de11`:

- C7/01 запрос списка; C7/02 записи; C7/03 удаление; C7/04 очистка. Диспетчер `7d02d8`, чтение записей `7cffb0`.
- 21 отправка чата, 22 получение. Чтение ответа `9fed8c`, UTF-16 reader `605df4`. Привязки вкладок этой версии: «Глобальный» 12, «Торговля» 6, «Помощь» 8, приват 1. Канал 0 ограничен локацией. Каналы 6/8/12 сейчас общесерверные — это явно выбранная политика эмулятора. Список справа всегда ограничен локацией, независимо от вкладки.
- **68/00 + имя** — запрос информации (`96d568`); префикса C8 у него нет. A7/00 — ответ (`96d7d0`).

`tools/verify_presence_native.py` выполняет оригинальные ветви чтения списка; `tools/verify_social_native.py` — оригинальный построитель запроса профиля и чтение скалярных/UTF-16 полей ответов. Выделение строк, ANSI reader и интерфейс заменены явно описанными заглушками. Результат записан в `evidence/social_native.json`. Это проверка совместимости пакетов, а не подтверждение поведения двух настоящих окон игры.

Автоматические тесты проверяют два TCP-клиента, список, русское сообщение, чужую карточку, удаление отключившегося игрока; отдельно — изоляцию локаций/личной переписки и чтение статистики без записи в базу.

Не реализованы в этом обновлении: клановый/альянсовый и боевой чаты, команды модерации и история переписки. Неизвестные каналы отклоняются, а не рассылаются всем. Окончательная проверка кликов, отображения статуса и вкладок нужна в оригинальных клиентах.

## Обновление VPS

Архив содержит весь текущий сервер, включая ранее подготовленные командные лобби. Он не содержит базу, пароли и клиентские ресурсы. Конфигурация `/etc/tio-server/server.toml` остаётся прежней, нужен `multi_account = true`. Порты прежние: 28512 и 28513.

1. Завершите бои и закройте оба клиента.
2. В **Windows PowerShell** загрузите архив:

```powershell
scp C:\TIO-emulator\data\tio-city-social.tar.gz root@185.184.42.88:/root/
```

3. Подключитесь из Windows PowerShell командой `ssh root@185.184.42.88`.
В **SSH на VPS** выполните целиком (веб-терминал хостинга может добавлять к вставке лишние символы):

```bash
(
set -e
test -f /root/tio-city-social.tar.gz
test ! -e /root/tio-before-city-social.tar.gz
systemctl stop tio-server
runuser -u tio -- /opt/tio-emulator/.venv/bin/python /opt/tio-emulator/deploy/scheduled_backup.py --source /var/lib/tio-server/reservation.sqlite3 --directory /var/backups/tio-server --tag pre-update
tar --exclude=.venv --exclude=__pycache__ -czf /root/tio-before-city-social.tar.gz -C /opt/tio-emulator .
tar -xzf /root/tio-city-social.tar.gz -C /opt/tio-emulator --no-same-owner
cd /opt/tio-emulator
runuser -u tio -- .venv/bin/python -m server --config /etc/tio-server/server.toml --check
systemctl start tio-server
sleep 2
systemctl is-active tio-server
journalctl -u tio-server -n 25 --no-pager
)
```

При ошибке блок останавливается. Если ошибка произошла до распаковки, можно запустить прежний сервер: `systemctl start tio-server`. Если новый код уже распакован, восстановите сохранённый код:

```bash
systemctl stop tio-server
tar -xzf /root/tio-before-city-social.tar.gz -C /opt/tio-emulator --no-same-owner
systemctl start tio-server
```

Откат кода не откатывает результаты боёв и базу. Зависимости устанавливать не нужно. Новые модули при откате могут остаться на диске, старый код их не импортирует.

## Проверка с другом

1. Войти двумя разными аккаунтами в Reservation. Каждый должен увидеть оба ника справа.
2. Написать по-русски во вкладках «Глобальный», «Торговля», «Помощь». Проверить получение другим игроком.
3. Выбрать ник друга и информацию: заголовок должен содержать его имя. В «О себе» — его данные, а не ваши.
4. Отправить личное сообщение выбранному нику. Если участвует третий тестировщик, он не должен его получить.
5. Одному перейти в другой город: списки должны разделиться. Общесерверные вкладки продолжают работать.
6. Одному выйти из игры: его ник должен исчезнуть у второго. При повторном входе — появиться.
7. Проверить статус во время боя и после возвращения. При проблеме сохранить скриншот и свежий журнал `journalctl -u tio-server --since '5 minutes ago' --no-pager`.
