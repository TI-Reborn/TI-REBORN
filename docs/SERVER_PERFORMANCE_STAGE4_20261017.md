# Пустые транзакции контрактов, групп и SC-аукциона — 17.10.2026

## Изменение

Пакет содержит три файла:

* `tio/pve_contracts.py`: `get`, `active`, `target_for` читают согласованный
  снимок без writer transaction, если подходящих просроченных контрактов нет.
  `expire` при отсутствии работы возвращает пустой результат. При положительной
  проверке read snapshot закрывается до получения writer lock, затем исходный
  `_expire` заново проверяет сроки и выполняет изменения атомарно. Глобальное
  истечение при get/target_for и ограничение конкретной группой при active сохранены.
* `tio/travel_party.py`: `set_online` не открывает writer, когда статус и запись
  об отключении уже согласованы; `recover_leader` не открывает writer, когда
  замена лидера не требуется. Проверки принадлежности персонажа сохранены.
  Для реальных изменений состав, статус, срок ожидания и кандидат проверяются
  повторно под writer lock. Уже начавшиеся игровые транзакции не коммитятся
  и не закрываются внутренними store-вызовами.
* `tio/sc_auction.py`: фоновый `tick` проверяет наличие работы чтением.
  Учитываются конец лота, последняя секунда автоматического лота, истечение
  невостребованного выигрыша, отсутствующие предложения и лимит живых лотов.
  При положительной проверке полностью выполняется исходный writer-путь:
  `_tick`, выбор допустимого бота, списания, возвраты, события и пополнение.

Проверка автоматического лота намеренно консервативна: в последнюю секунду
writer разрешён даже при отсутствии подходящего бота. Случайный выбор бота не
вызывается во время предварительного чтения. Частота опроса, игровые сроки,
тарифы, выигрыши, формат пакетов и конфигурация не меняются. Долговременного
кэша сроков, аккаунтов или состояний нет. После простоя пропущенное окно
по-прежнему закрывает лот без задним числом сделанных ставок.

## Измерения

Изолированная SQLite на VPS, 30 повторов после прогрева, четыре разных аккаунта
в группе, SC-каталог из трёх предложений. Строки всех таблиц до/после пустых
проходов совпали; хеши возвращаемых результатов исходной версии и кандидата
также совпали во всех сценариях.

| Операция | Writer begin до → после | SELECT до → после | Медиана на VPS до → после |
|---|---:|---:|---:|
| Статусы/лидер/цель контракта для четырёх участников | 12 → 0 | 56 → 52 | 11,59 → 11,67 мс |
| Цель контракта при отсутствии контракта | 1 → 0 | 2 → 2 | 0,88 → 0,81 мс |
| Пустой проход SC-аукциона | 1 → 0 | 8 → 2 | 1,61 → 0,93 мс |

Для группы изолированная задержка на VPS не улучшилась: результат этого
изменения — устранение лишних захватов общей блокировки записи SQLite.
Ожидаемое снижение конкуренции с другими игровыми операциями нужно оценивать
под совместной нагрузкой; фиксированное ускорение всей игры не обещается.
Замеры последовательные, текущая фоновая нагрузка VPS не фиксировалась одинаковой.
Локальные замеры также сохранены в отчётах.

## Проверки

Добавлены 16 тестов. Они проверяют отсутствие writer на пустых проходах,
точные границы сроков, единственное событие при конкурентном истечении,
продление контракта и лота между чтением и записью, возврат лидера до замены,
исчезновение участника, восстановление disconnect-записи, откат ошибок,
сохранение внешней транзакции, последнюю секунду бота, закрытие, истечение
выигрыша, пополнение и заполненный лимит лотов.

Исходный hosted-код прошёл 120 применимых тестов, кандидат — 136 локально
и в отдельной копии на VPS. Семь старых тестов падают одинаково до и после:
они ожидают старые номера контрактных зон 18–20 и двадцать зон вместо текущих
23–25 и двадцати пяти зон. В частности, старый тест дублирования ID использует
константу 18, которая больше не совпадает с ID первого шаблона. Исключения
применены только по точным именам, включая родительский тест одного subTest.
Конфигурация `contracts-local.toml`, отсутствовавшая в hosted-дереве,
предоставлена только изолированным тестовым копиям. Runtime-каталог и валидатор
зон не изменялись. Весь репозиторий не объявляется прошедшим тесты.

До установки проверены два публичных TLS-подключения с зарезервированными
QA-логинами, исключёнными из рейтингов. Проверены общая комната, ID участников,
частная группа и её роспуск, SC-каталог и обновление у обоих без ставок,
принятие контракта, видимость цели обоим участникам, отмена, снятие блокировок
и скрытие цели. Балансы и инвентари QA не изменились. Контракт и аккаунты удалены
по точному владению, чужие строки сохранены; осталось 19 аккаунтов,
integrity_check=ok. Финансовые гонки и срабатывание таймеров проверяются на
изолированных базах; ставки в публичные реальные лоты ради QA не делаются.
Графические клиенты отдельно не проверялись.
