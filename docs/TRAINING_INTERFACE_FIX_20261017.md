# Кнопки групп на тренировочных базах

Дополнение 18 октября: исправление `base4` было необходимым, но недостаточным.
Настоящий графический клиент выявил сброс вкладок, проверку клана, неверный
формат строк в пакетах и несовпадение переключения готовности. Все эти причины
разобраны в [итоговом отчёте Training Base](TRAINING_BASE_20261018.md).
Опубликовано обновление клиента `2026.10.18.1`.

На двух скриншотах клиента виден старый интерфейс с Нападением/Защитой и без
создания групп. Проверка опубликованного и серверного zones.xml установила,
что базы 19–22 имеют type=base. Это выбирает Assault3. IsTraining=true не
переключает поколение штурмов.

Оригинальный загрузчик 9ea894 устанавливает town+255 только для type=base4
(сравнение 9eaaee, запись 9eaaff). Обработчик TownInfo 7cf3f4 пропускает новую
зону, если флаг не установлен; 7d2ef2 выбирает соответствующий режим интерфейса.
До исправления новый ZoneInfo поэтому не использовался нужным обработчиком,
хотя часть общих полей позволяла отображать время/туры в старом окне.

Выполнены original-instruction проверки на всех четырёх базах до/после:
до — Assault4 branch пропущен, после — выбран. Отдельно пройдены оригинальный
загрузчик всех 22 городов, 44 проверки видимости, B9 shared config и порядок
трёх коэффициентов. XML DOM/RTL/allocation/UI helpers изолированы; это не
подтверждение пикселей настоящего клиента или боя восьми людей.

Опубликовано 2026.10.17.2: только type base -> base4 для городов 19–22 в
серверном каталоге и launcher blob. Остальные файлы manifest, включая DLL
ремкомплектов, сохранены. Изменение не требует перезапуска tio-server.
База игроков не заменялась. До публикации сохранены online SQLite backup
с integrity_check=ok, старый код/конфигурация, оба XML, manifest и service unit:
`/root/tio-before-training-interface-klernhgv`.

Публичный manifest и blob повторно скачаны через доверенный HTTPS, SHA256
совпали. При повторном входе сервер передаёт каталог; запуск через лаунчер
также обновит исходный XML. Открытое окно старой сессии не является проверкой
нового каталога. Графическая доступность создания/вступления/готовности и
полный hosted бой остаются отдельной приёмкой, пока не заявляются пройденными.

Оригинальное объявление администрации от 13.12.2013 описывает создание БГ
во время регистрации/перерывов и четыре игрока с 1–3 наёмниками каждый.
Для клановых штурмов автор группы состоит в клане, вступают сокланы/соальянсеры.
Исторические требования именно бесклановой тренировочной базы из этой статьи
не следуют; их нельзя выдавать за подтверждённые. Текущий серверный TrainingArena
допускает разные реальные аккаунты без кланового ограничения.
Источник: https://ggeek.ru/forum/ggeek-forum-20-blog-administratsii/forum-3430-shturmy-new/

Проверки/публикация: `reports/training-status-20261017/training-interface-proof.json`,
`hosted-candidate-native.json`, `publication.json`, `https-verification.json`.
Инструменты: `tools/check_training_interface_20261017.py`,
`tools/publish_training_interface_20261017.py`.

Старый stage8 generator и его frozen fixtures не переписаны под видом нового
релиза. При будущей генерации тренировочных строк нужно сохранять type=base4;
проверка verify_world_catalog_native теперь явно контролирует этот флаг.
