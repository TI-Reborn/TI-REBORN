# Анализ передачи, 17.10.2026

## Что исправлено в организации

- Отдельная чистая копия исходников по явному списку включения. Рабочие данные владельца
  и исходный каталог не перемещаются. `SOURCE_MANIFEST.json` фиксирует исходные хеши.
- Новый README и инструкции на русском; старые статусы выделены как исторические.
- Карта ответственности и автоматически построенный индекс модулей/документов.
- Пример multi-account конфигурации с loopback и отдельной базой разработки.
- Игнорирование секретов, баз, отчётов, сборок, дампов и виртуальных окружений.
- CODEOWNERS, шаблон PR, базовый CI без deploy и проверка состава handoff.
- Python minimum в метаданных приведён к 3.11: код использует `tomllib`.

## Выводы и следующие улучшения

1. `tools/loopback_exchange.py` — большой центральный обработчик, а не только диагностика.
   Разделять по сервисам постепенно, с TCP-регрессионными тестами; массовый перенос сейчас
   изменил бы риск передачи и затронул deployment-скрипты.
2. `server/team_arena.py` — крупный координатор боя. Выделение жизненного цикла матча,
   доставки событий и восстановления требует отдельной задачи и проверки двух клиентов.
3. Старый README смешивал недавние изменения и первоначальные незавершённые эксперименты.
   Новая точка входа отделяет описание устройства от исторических утверждений о готовности.
4. Схемы SQLite распределены по модулям. Следующая полезная задача — реестр миграций
   и тест обновления сохранения, без автоматической переписи production-данных.
5. `tools/` содержит сотни исследовательских и release-утилит. Они сохранены ради импортов
   тестов и воспроизводимости; переносить в `tools/research`, `tools/qa`, `tools/release`
   стоит отдельными PR после проверки ссылок, а не при передаче.
6. Packaging metadata исторически описывает исследовательский пакет `tio`, а сервер
   запускается из checkout. Отдельная задача — полноценный wheel/контейнер с ресурсами.
7. Полный suite смешивает server, client, сайт и исследовательские зависимости.
   Базовый CI должен быть явно ограничен воспроизводимыми серверными проверками;
   список расширенных проверок и отсутствующих ресурсов — в VALIDATION.md.

Скорость игровой логики не оптимизировалась: профилирования под нагрузкой не было.
«Оптимизация» этой передачи касается структуры, документации и процесса разработки.
Исчерпывающий аудит безопасности каждой строки и нагрузочная аттестация не выполнялись.
