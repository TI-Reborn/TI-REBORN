## Подключённые операции

`server/market_operations.py` использует общий `OperationRegistry` нашего
сервера. В нём 13 команд:

| Подсистема | Команды |
| --- | --- |
| Обмен игроков | окончательный расчёт после двух подтверждений |
| Личные лавки AE | публикация продаж/заявок покупки, подпись, покупка и продажа по заявке |
| Обычный аукцион C8 | создание лота, ставка, снятие, быстрый выкуп |
| SC-аукцион | ставка, установка/удаление автобота, оплата выигранного лота |

Приглашения и выбор предложений обмена сохраняют существующий механизм
черновика. Деньги и вещи передаются после двух подтверждений и повторной
проверки участников. Входящие пакеты декодируют прежние адаптеры.
Команды хранят неизменяемые снимки аргументов, контекст — подтверждённого
сервером владельца, store, транзакцию, время и текущий допуск.
Перед выполнением проверяется принадлежность одной SQLite и заново
выполняется проверка сцены. Адаптер C8 получает hub lock и live gate города.

Доменные `TradeStore`, `PrivateShopStore`, `AuctionStore`, `SCAuctionStore`
сохраняют цены, залог, ограничения предметов, версии, доставку и журналы.
Новые таблицы, сброс сохранений и изменение баланса не вводятся.
Это организация нашего кода, без переноса движка/данных Unity-проекта.

## Повторы и атомарность

- Обмен: повтор завершения не передаёт вещи заново; сохраняется immutable receipt.
- C8: повтор создания с прежним session/request возвращает тот же лот;
  устаревшая ставка/выкуп закрытого лота отклоняются. Повтор снятия своего
  уже снятого лота не возвращает вещи второй раз.
- AE: покупка после изменения/погашения котировки отклоняется; store сохраняет
  прежнюю квитанцию ID сделки. Нового клиентского nonce в старом протоколе нет.
- SC: повтор против той же открытой формы/котировки использует прежнюю
  durable-квитанцию; новое открытие означает новое намерение.

`market_unit` объединяет доменные записи и подготовку ответа в одну
транзакцию/savepoint. Ошибка хранения, неверный результат или сбой ответа
откатывают деньги, вещи, залог и квитанцию. AE/SC восстанавливают локальные
котировки и токены. В обмене пакеты успешного завершения готовятся внутри
транзакции и ставятся в очереди обоих участников **после commit**.

`AuctionStore` умеет присоединяться к внешней транзакции: leased-курсор
возвращает `sqlite3.Row`, не меняя row factory внешнего соединения и не
выполняя самостоятельный commit. Фоновое закрытие истёкших лотов прежнее.

## Проверки

```powershell
python -X utf8 tools/check_trade_operations.py
python -X utf8 tools/check_trade_operations.py --baseline-only
python -X utf8 tools/check_trade_qa_cleanup.py
```

Кандидат: **134/134**, включая 24 новые проверки. Неизменённый hosted-снимок:
**110/110** прежних проверок. Ещё две проверки очистки QA подтвердили
сохранность обычных аккаунтов, user-created `TestClan` и отказ от удаления
сделки с чужим участником. Проверяются конкурирующие покупатели, возврат
ставки, метаданные, отмена/reconnect, защита чужого лота, rollback обоих
кошельков, одна физическая вещь, SC fee/bot/claim/replay и отсутствие
самопроизвольного открытия закрытого окна. TCP-тесты используют отдельные
сокеты, но не графические клиенты.

Тест городского окна теперь ждёт `1A` перед ping: он не объединяет фазовые
запросы `19`/`70` в один TCP read. Проверяющий скрипт закрепляет dispatcher
выбранного snapshot, чтобы локальные и hosted-модули не смешивались.
