# Training Base: список созданных групп

Дополнение 18.10: вместо нулей для существующих значков передаются их настоящие
ID; значки видны в списке групп и «Моей группе». Нулевые значения сохраняются
для игроков без значка. [Исправление и проверка на хостинге](CLAN_CREST_PROJECTIONS_20261018.md).

Список находится справа во вкладке **«Боевые группы»**. Строка показывает
число игроков относительно четырёх мест и имя создателя. В свободную группу
игрок входит кнопкой **«Вход»** в соответствующей строке; после выбора бойцов
открывается **«Моя группа»**. Слева таблица «Игроки / Место / Ник / Очки»
служит для результатов участников и не заменяет каталог групп.

## Источники

Оригинальный [мануал Total Influence](https://ti.ggeek.ru/files/TIO_manual.pdf),
раздел «Штурмы и базы → Подготовка к штурму», пункты 1, 3 и 4: созданные группы
отображаются в окне формирования, присоединение выполняется кнопкой «ВХОД».
Локальная извлечённая копия: `reports/chat-presence/manual.txt`, строки 4768–4797.
Это описание старого штурма; расположение интерфейса подтверждено кодом
установленного клиента. Для текущего Assault4 [объявление администрации](https://ggeek.ru/forum/ggeek-forum-20-blog-administratsii/forum-3430-shturmy-new/)
указывает четыре игрока по 1–3 наёмника.

## Причина пустого списка

Сервер передавал список `C8/26` и рассылал изменения игрокам в одной базе.
Но `RoomListItem` содержал отсутствующие значения значков клана и альянса.
Оригинальный reader `0x63aa10` допускает их отсутствие на уровне пакета,
а потребители списка `0xa08b20` и `0xa08c68` безусловно вызывают обязательные
getters `0x63add8` и `0x63ae3c`. Первый отсутствующий значок вызывает исключение
до добавления строки; поэтому интерфейс выглядел пустым даже при двух группах.

`TrainingArena._training_list()` теперь передаёт присутствующие значения `0`
для обоих значков. Это означает отсутствие изображения значка, сохраняя
требуемый клиентом формат. Идентификаторы, имена, заполненность и готовность
остаются серверными. Правка касается только списков Training Base.

Исходная DLL клиента 2026.10.18.2 не меняется. Изменяется только
`server/training_arena.py` на основе проверенного актуального файла хостинга.
Локальные несвязанные отличия в производительности в пакет не включены.

## Проверки и развёртывание

Результаты сохраняются в `reports/training-groups-20261018/`.
`native-crest-getters.json` проверяет исходный машинный reader и оба getters
в 16 вариантах имени, заполненности и готовности: отсутствующие значения
воспроизводят исключение, присутствующий ноль возвращается корректно.
Управляемые строки изолированы тестовым стендом; это не проверка GUI.

`tests/test_training_group_list.py` проверяет две одновременно созданные
группы и выбор второй, создание/вступление/выход/роспуск, очистку списка,
разделение баз и запрет пятого участника. Пакет автоматических тестов
выполняется в изолированной копии актуального сервера со временными БД.
Пройдено 69 автоматических тестов за 100 секунд, два штатно пропущены.
Новый тест первоначально ошибочно ожидал исключения от общего обработчика,
который возвращает сообщение об отказе, и читал раннее уведомление из очереди;
проверки приведены к фактическому внешнему поведению обработчика.

После развёртывания проверены один настоящий Windows-клиент и второй аккаунт
через TLS-протокол. Клиент показал имя создателя, «1/4» и «Вход». Нажатие
открыло выбор бойца, затем «Моя группа» с обоими аккаунтами. Число участников
стало «2/4», после выхода рядового участника — «1/4». Роспуск удалил строку,
новая группа появилась без повторного открытия вкладки. Это проверка двух
серверных аккаунтов, но только одного графического клиента.

Машинные события записаны в `native-before.jsonl` и `native-after.jsonl`;
GUI-наблюдения — `gui-verification.json`, протокол второго аккаунта —
`peer-verification.json`, изолированные тесты — `remote-checks.json`.

Сервер обновлён с коротким перезапуском при отсутствии сохранённых боёв и
незавершённых расчётов. Резервная копия БД на момент переключения, предыдущего
кода и конфигурации:
`/root/tio-before-game-operations-training-groups-20261018`.
При замене кода все 171 таблица сохранены; локальные игровые данные
не загружались. После проверки удалены ровно два собственных QA-аккаунта.
Существовавшие 19 аккаунтов сохранены. Отдельное сравнение с БД в момент
переключения подтвердило неизменность строк существующих аккаунтов,
персонажей, наёмников, кошельков, складов, кланов и членства в кланах
(`player-runtime-audit.json`). Очистка не меняла посторонних строк.
Флаг сравнения с более ранним моментом создания фикстур в
`fixture-cleanup.json` равен false; это отдельный снимок до развёртывания,
его нельзя трактовать как равенство всех данных за весь период работы.

Итог: `integrity=ok`, `tio-server` активен, PID `127076`, `NRestarts=0`.

`f1e5dcd0f1d538307341dcdb467887e7521e0777470d449b3671c66f7b40b8ab`.
Клиентский манифест и DLL версии 2026.10.18.2 не менялись.
