# Редактор предметов и баланса

Первая версия, 15 октября 2026. Локальный инструмент разработки поверх каталогов
нашего TIO Reborn. Не изменяет игровой код, сохранения или хостинг.

## Запуск

Дважды щёлкните `C:\TIO-emulator\tools\Start-BalanceEditor.cmd`.
Требуется установленный Python 3.11 или новее; дополнительные пакеты не нужны.
Откроется `http://127.0.0.1:8766/`. Повторный запуск открывает уже работающий редактор.
Окно командной строки можно оставить открытым; Ctrl+C останавливает сервер.

Альтернатива из корня проекта:

```powershell
python tools/balance_editor.py --open
```

Другой локальный порт: `python tools/balance_editor.py --port 8767 --open`.
Сервис привязан только к `127.0.0.1`; это не публичная административная панель.
Проверяется Host/Origin, запросы API требуют случайный токен текущего процесса.

## Работа с профилями

1. Нажмите «Новый профиль». Основа — текущие **локальные** каталоги проекта.
2. Найдите предмет по имени или ID, либо выберите категорию.
3. Измените доступные значения. Янтарным отмечены отличия от исходного снимка.
4. Сравните исходный баланс и профиль на графике. Броня цели и запас ОД —
   параметры предпросмотра; они не сохраняются как изменения предмета.
5. Откройте «Посмотреть изменения», затем сохраните профиль.
6. «Профиль JSON» выгружает переносимый профиль со снимком основы.
   «Импорт» создаёт отдельную копию, не перезаписывая существующий профиль.
7. «Экспорт кандидата ZIP» формирует материалы для проверки и дальнейшей интеграции.

Ctrl+S сохраняет профиль; Ctrl+K переводит фокус в поиск. Последний открытый
профиль восстанавливается при следующем открытии в том же браузере.
Профили сохраняются в `data/balance-editor/profiles/<id>.json`.
Не удаляйте их при обычной очистке временных QA-файлов: это рабочие материалы пользователя.

У профиля есть ревизия. Одновременная запись из двух окон не затирает изменения:
второе сохранение получает конфликт. Несохранённые правки остаются в окне;
их можно просмотреть и затем загрузить актуальную ревизию через переключатель.
Если изменились исходные файлы, сохранение и экспорт кандидата блокируются.
Нужен новый профиль на актуальной основе; автоматического переноса правок на
изменившиеся каталоги в первой версии нет. JSON старого профиля можно сохранить
как материал для ручного согласования.

## Что редактируется

- Оружие: базовый и добавочный урон, ОД, дальность, точность и её прибавка,
  остаток урона вдали, критический шанс, ссылка на боеприпас, расход за атаку.
- Броня: базовая защита; вес.
- Вес предметов из XML; цены из кредитной политики за указанный размер упаковки.
- Для особых предметов доступен только поддержанный набор полей.

Режимы оружия, типы экипировки, новые ID, модели, текстуры и перезарядка здесь
не создаются. Боеприпасы — расход за атаку, не размер магазина.
Лечение и ОД обычных аптечек закреплены в `MEDICAL_ITEMS` игрового кода и здесь
не меняются. Аналогично защищены отдельные правила мин и жилета смертника,
часть параметров взрывов и расхода гранат. Цена Upgrade Kit закреплена
серверной проверкой и доступна только для просмотра.

Открываются все 162 текущие записи, включая служебные. Объём каталога
определяется файлами, а не зашитым числом. Служебные валюты, базовые модели
и неподдержанные поля показаны только для просмотра.

## Предпросмотр

Используются реальные `WeaponCatalog.distance_damage`, `WeaponCatalog.accuracy`
и `armor.mitigate`, с отдельным учётом того, что у взрывного оружия нет
падения урона от расстояния до точки броска. График показывает диапазон
**успешной атаки**, для очереди — попадание всех пуль. Средний урон / ОД —
среднее концов этого диапазона, делённое на стоимость атаки.

Это не ожидаемый урон с учётом вероятностей и не симулятор полного боя.
Навыки, улучшения, криты, отдельные промахи пуль, укрытия, горение и число
целей не моделируются. Для мин и служебных спецэффектов обычный график не
показывается. Предпросмотр брони показывает отдельную часть экипировки,
без остальных частей и улучшений.

## Согласование данных при экспорте

Исходный снимок закрепляет SHA-256 восьми файлов:

- `config/weapon_catalog.json`
- `evidence/items_diagnostic.xml`
- `config/battle_item_catalog_extension.json`
- `config/battle_item_catalog_extension.xml`
- `config/battle_item_effects.json`
- `config/credit_economy.json`
- `config/city_catalogs.json`
- `config/sc_catalog.json`

Кандидат обновляет канонические и производные представления: поля оружия и
его `source_fields`, XML-значения и существующий `<for>`-блок с уроном,
точностью, защитой и расходом, соответствующие overlays и таблицы спецэффектов.
Незатронутые файлы сохраняют исходные байты.

Цена обновляется в кредитной политике и предложениях с тем же ID и размером
упаковки. Предложения с другим размером упаковки не пересчитываются. Историческое
поле `gold` в premium-списке несёт цену в кредитах согласно действующей
политике проекта; новая Gold-валюта не создаётся. Исходный исторический справочник
`original_shop_prices.json` не переписывается.

ZIP содержит `profile.json`, `changes.json`, `manifest.json`, `README.ru.txt`
и восемь файлов в `candidate/`. В manifest указаны хеши основы и кандидата.
Базы игроков, пароли, серверная конфигурация и скрипты применения в ZIP не входят.

**ZIP не является готовым обновлением сервера.** Перед применением требуется:
сверить актуальные удалённые каталоги, согласовать изменение баланса, подготовить
публичный клиентский `items.xml` и кэш Unity, выполнить предписанные резервные
копии и интеграцию, затем проверить хостинг и два реальных клиента.
`items_diagnostic.xml` — серверный источник; он не автоматически заменяет
публикуемый клиентский XML. Локальный снимок не объявляется копией хостинга.

В этой задаче изменение игрового баланса и его развёртывание не выполнялись:
реализован инструмент для подготовки проверяемого предложения.

## Проверка

```powershell
python -m unittest tests.test_balance_editor -v
node --check tools/balance_editor_ui/app.js
```

20 автоматических проверок: допустимые значения, ссылки патронов, производные
JSON/XML, спецэффекты, упаковки, серверные формулы, атомарная запись, конкуренция
двух сохранений, изменение основы, импорт, состав/хеши ZIP, Host/Origin/token
и полный HTTP-проход создания → сохранения → экспорта.

Проверка настоящим браузером: создание рабочего профиля, AK 47 50→60 и ОД 5→4,
сохранение, перезагрузка, пересчёт при броне 100 (25–37→30–42), скачивание ZIP,
ошибка дальности и запрет сохранения, затем сброс проверочных значений.
Это проверка редактора, не multiplayer-тест игры. Рабочий профиль оставлен
без экспериментальных изменений.

Код: `tools/balance_editor_core.py`, `tools/balance_editor.py`,
`tools/balance_editor_ui/`; тесты: `tests/test_balance_editor.py`.
