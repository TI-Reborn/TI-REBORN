# Продолжение контрактов в облаке

Пользователь 24 октября попросил выполнить эту работу в облаке, поскольку выключает компьютер. Это полное задание для автономного продолжения. Пока реализация новых требований не начата. Ветка `codex/contracts-expansion-20261024` содержит актуальные исходники, а не только план.

## Требования

1. Вверху нативного окна контрактов сделать три кнопки: «Одиночные», «Групповые», «Моя группа». Сохранить оформление игры; окно подборa «стенка на стенку» — образец.
2. Добавить одиночные контракты для одного настоящего аккаунта против собак, мутантов и рейдеров. Групповые по-прежнему должны поддерживать несколько настоящих аккаунтов с общей авторитетной серверной сессией.
3. Увеличить награды групповых контрактов в 10 раз. Исходные награды: лагерь 150 кредитов/60 опыта, склад 180/75, КПП 200/80 каждому участнику. Значит новые групповые награды 1500/600, 1800/750, 2000/800.
4. Премиум не увеличивает награды контрактов. Антиопыт должен обнулять весь опыт контракта, включая фиксированную награду. Не ломать премиум в обычных режимах.
5. После убийства босса контракта появляется обычный игровой рюкзак, как после убийства игрока на арене. Использовать существующие нативные пакеты и механизм предметов/контейнеров.
6. Разработать понятную вероятностную таблицу выпадения оружия с заточкой до +10. Итоговый предмет должен работать в инвентаре и бою, а выпадение и получение должны быть защищены от повторной выдачи, перезапуска, переподключения и конкурирующих запросов игроков.
7. Автоматическое завершение/выход из боя блокируется, пока рюкзак босса не собран. После сбора завершение возобновляется. Учитывать серверный журнал боя, восстановление, отключения и групповой доступ к луту.

## Точный исходный снимок

`server/`, `tio/`, `config/`, `evidence/` скопированы с фактически работающего хостинга ночью 24 октября. `launcher/` — чистые исходники опубликованного 0.1.33. `tools/`, `deploy/`, `tests/`, `docs/` взяты из текущей локальной рабочей области. Файл `docs/CONTRACTS_CLOUD_SOURCE_SHA256.json` фиксирует контрольные суммы исходников до реализации. Базы игроков, пароли и SSH-ключи не передаются.

Не перезаписывать эти файлы старой версией из main или старым локальным репозиторием. Важно: актуальные приватные зоны контрактов **23, 24, 25**, а старые локальные тесты иногда ожидают 18, 19, 20. Публичные зоны 1–22 должны оставаться доступными.

## Где изменять

- `tio/pve_contracts.py`: каталог, допустимые размер группы/профили врагов, фиксирование задания и наград, durable состояния/receipts.
- `server/contracts_service.py`, `server/contracts_ui.py`: авторитетные команды, подписанные сессии UI и списки контрактов.
- `server/contracts_combat.py`: сейчас `finish_contract` немедленно завершает контракт и возвращает группу в город. Добавить надёжную фазу сбора лута, сохранив атомарность journal/settlement и повторяемость.
- `tio/contract_scene.py`: профили NPC, боссы, визуальное представление.
- `tio/battle_loot.py`, `tio/arena_service.py`: существующие рюкзаки и их получение. Запросы клиента 0x46 открытие, 0x40 перенос. Не изобретать отдельную награду вместо выпавшего рюкзака.
- `tio/battle_rewards.py`: последние исправления премиума и антиопыта уже включены. Фиксированная контрактная награда сейчас добавляется после премиумного множителя опыта, поэтому антиопыт пока её не гасит. Обычные режимы не менять.
- `launcher/NativeContractsUi.cs`, `deploy/client_contracts_windows.py`, `launcher/Assets/native-contracts-windows.json`: нативный интерфейс (сейчас 57 записей). При добавлении третьей вкладки согласовать количество записей, индексы и обработчики на Python/C# и пересоздать JSON генератором.

## Проверки и выкладка

Следовать корневому AGENTS.md. Хост `root@185.184.42.88`, service `tio-server`, source `/opt/tio-emulator`, config `/etc/tio-server/server.toml`, data `/var/lib/tio-server`, SQLite `reservation.sqlite3`. Сначала прочитать реальное состояние хоста. Не предполагать доступ к SSH: приватный ключ остался только на локальном компьютере, использовать исключительно уже настроенные облачные секреты. Если доступа нет, закончить доступную реализацию и проверки, сохранить результат в ветке/PR и явно сообщить, что выкладка блокирована доступом.

Перед выкладкой сделать резервную копию удалённой БД и прежних кода/конфига. Никогда не переносить локальные данные игроков на хост. `tools/deploy_game_operations_remote.py` выполняет staging, резервирование, CAS-проверку исходников, безопасную остановку и проверки сохранения данных. Добавить отдельный allowlist scope для изменённых файлов. Не подменять весь хостинг локальной копией. На хостинге остаётся около 5.2 GB свободного места, не плодить полные копии клиента.

Обязательны тесты solo/group авторизации, переходов, наград ×10 и premium/anti-XP; вероятностей/предела +10; ровно одного выпадения/получения при replay/reconnect; настоящих пакетов открытия/получения рюкзака; блокировки автоматического выхода до сбора. Затем серверный preflight и фактическая проверка хостинга. Автотесты и протокольные QA не называть проверкой реальными GUI-клиентами.

QA аккаунты должны быть исключены из публичных рейтингов с самого создания: reserved namespaces из `tio/rating_visibility.py` либо предварительный `rating_exclusions`. Удалять только свои временные фикстуры. Никогда не удалять TestClan или обычных игроков.

Для лаунчера использовать чистую папку `launcher/`, новая версия предположительно 0.1.34, но сначала проверить текущую публикацию. `tools/prepare_launcher_publication.py`, `tools/run_launcher_update_publication.py`, `tools/verify_published_launcher_update.py` — резервирование, публикация и внешняя проверка. Не выкладывать непроверенный бинарник. Linux среда может потребовать .NET 10 и EnableWindowsTargeting для Windows publish; GUI-проверка требует реального Windows клиента и отдельно учитывается в отчёте.

Последние подтверждённые работы: премиум исправлен и проверен на хостинге, кнопки выровнены и опубликованы в 0.1.33. Текущие новые требования ещё не реализованы. Не выдавать сохранение исходников за завершение задачи.
