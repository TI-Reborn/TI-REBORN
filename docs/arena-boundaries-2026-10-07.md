# Декоративные границы A — версия 2026.10.07.3

На хостинге 185.184.42.88 опубликованы границы для всех 24 городских сцен:
четыре города × три случайных окружения × размеры 38 и 57 клеток.
Reservation использует низкий бетонный бордюр, Denver — 16 разных камней
со мхом и папоротниками, New York — родной тротуар с водостоками,
Military zone — низкий бетон с предупреждающей окраской и поручнем.
Каждый периметр включает четыре стороны и четыре угла.

Граница — неинтерактивная графика. Игровые клетки, AP, коллизии, LOS,
серверные карты и штатные исполняемые файлы не изменены. Постоянное
внешнее затемнение B1/255 из версии .2 сохранено, старые 552 TILE и 552 PNG
остались побайтно прежними.

## Сборка и регистрация

`tools/build_arena_boundaries.py` создаёт восемь общих периметров,
добавляет 54 TILE/54 PNG и дописывает модели к исходным 24 SET. Новые
патчи наследуют имя индекса, anchor, signed offset, размеры, flags и
culling соответствующего старого патча. Компенсация native foreground
по X составляет −32 пикселя. Патчи старой сетки не пересекаются; новая
модель добавляется после исходной в том же anchor, сохраняя порядок
обоих штатных способов обхода foreground.

Для исходных NY-спрайтов сохраняются пиксели 1:1. Совместимый tangent
срез — [3,4); прямые секции продлены на одну клетку за углы. Генерация
камней Denver сохранена в `assets/arena-boundaries-v1/generated-stones/`:
оригинальный atlas, точный prompt, 16 скомпилированных спрайтов и proof.
Плотность пикселей приведена одним одинаковым коэффициентом по обеим
осям; в клиенте спрайты отображаются 1:1.

При воспроизведении упаковки на Windows локальный
`asset-verification.json` следует сохранять точными байтами одноимённого
proof из одобренного `patch.zip`: JSON в архиве использует LF, тогда как
`Path.write_text` может создать CRLF. В этой публикации установлено
равенство JSON и отличие только CRLF/LF; локальный proof приведён к
точным одобренным байтам перед финальной проверкой. Прежний Windows
вариант сохранён отдельным диагностическим файлом.
