# Боты арены: выживание, командный бой и стенка

Изменение от 16 октября 2026 года для общего авторитетного сервера.

Одиночная заявка «Выживания» получает одного временного AI-соперника через
60 секунд готового поиска. Совместимые реальные игроки имеют приоритет.
Прежние правила групп из 2–4 игроков, уровней, городов и размера отряда
сохранены. Снятие готовности прекращает отсчёт; повторная готовность начинает
новую минуту. Бот имеет отдельного владельца боя и не создаёт аккаунт.

Боты в общих аренах начинают без личного снаряжения капитана. Для этого
используется уже существующая проекция пустой боевой копии; сохранённые
персонажи и предметы игроков не меняются. Каждый человекоподобный бот
сначала ищет ящик, открывает его обычным действием, забирает совместимое
оружие, нужные патроны, несколько лечебных предметов и подходящую броню.
При достаточном комплекте хватает одного ящика, иначе проверяется второй.
Содержимое ящика читается планировщиком только после открытия.

Переносимый вес включает надетые вещи. Первый штраф −3 AP в существующих
правилах начинается при 50% грузоподъёмности, поэтому бот ограничивает
подбор ниже этого порога. Базовый запас патронов ограничен шестью атаками,
лечебных предметов — тремя; вместимость сумки также проверяется. При
исчерпании боезапаса разрешён новый поиск припасов, до двух ящиков за ход.
Если патроны найти не удалось, пустое оружие убирается для ближней атаки.

При HP ≤70% бот использует имеющееся доступное лечение, учитывая реальную
стоимость AP и расход предмета. При обнаружении врага во время движения
план пересчитывается после каждого шага. Бот проверяет боезапас, дальность,
линию огня и цену атаки текущего оружия. При доступном укрытии резервирует
AP на одну атаку и путь из видимости всех известных вражеских наблюдателей.
После атаки путь пересчитывается по выжившим и вновь замеченным врагам.
Если уйти из видимости за оставшиеся AP невозможно, бот использует
доступную атаку либо сближение/отход без обещания недостижимого укрытия.

Планирование использует известные позиции и общее зрение своей стороны.
Скрытые позиции врагов не используются. Все действия выполняются через
те же серверные обработчики, что и команды игроков. Шаги, выстрелы,
открытие дверей/ящиков, экипировка и лечение проходят общие проверки.
Состояние сбора припасов входит в сохраняемый снимок боя. Индивидуальное
поведение шахтных мутантов сохранено.

Из обновлений видимости убраны повторные расчёты косметических эффектов
при промежуточном воспроизведении маршрута. Туман войны остаётся
пошаговым, итоговые визуальные состояния отправляются получателю.

Проверка на изолированной копии фактического серверного runtime:

```powershell
python -X utf8 tools/check_tactical_bots.py
python -X utf8 tools/prepare_tactical_bots_patch.py
```

Сценарии включают контакт после пяти шагов, разные цены выстрела,
сокрытие от нескольких известных врагов, неизменность плана при добавлении
невидимого противника, лечение, расход патронов, переносимый вес,
сбор/экипировку, пополнение боезапаса, сохранение снимка, подбор нескольких
реальных аккаунтов и изоляцию сохранённых вещей капитана. Дополнительно
проверяются восстановление после сбоев, общий бой, видимость, предметные
эффекты и погода.

В отчёте явно перечислены исключённые проверки статических исходных
ресурсов старого клиента. Старый набор Outpost требует исторического
runtime и несовместим с действующей проверкой здоровья при допуске;
изоляция личных вещей здесь проверяется на текущем runtime отдельно.

`tools/verify_tactical_bots_hosted.py` использует свежие случайные аккаунты
из зарезервированного QA-пространства, проверяет исключение из рейтингов,
проходит обычный TLS-протокол и проверяет общий сохранённый бой на сервере.
Отдельные сценарии: два реальных аккаунта в «Выживании», реальное ожидание
минуты для одиночной заявки, командный бой и стенка. При завершении
удаляются только записи этих точных QA-владельцев с проверкой сохранности
остальных данных. Это автоматические протокольные проверки; графические
клиенты ими не проверяются.

Артефакты проверки и поставки: `reports/bot-tactics-20261016/`.
Поставка через `tools/deploy_game_operations_remote.py --scope tactical-bots`
сверяет исходный снимок, отказывает при подключённых игроках/сохранённых
боях, проверяет кандидат, сохраняет прежний код/config и две целостные
SQLite-копии. На сервер заменяются только восемь файлов кода и политики;
локальные сохранения не загружаются. При ошибке откатывается код, а не БД.

Установка и проверка завершены 16 октября 2026: 233 автоматические проверки
прошли. На хостинге прошли все четыре протокольных сценария. Одиночный
бой обнаружен проверочным клиентом на 61,306 секунды; точная граница 60
секунд отдельно проверена управляемыми часами в автоматических тестах.
В одиночном, командном и стеночном боях зафиксированы открытие ящика,
экипировка бота и отсутствие штрафа за вес. Два реальных аккаунта в
«Выживании» получили общий бой без ботов.

Резервная копия: `/root/tio-before-game-operations-20261016-bot-tactics-b74e`.
При установке сохранены все 169 таблиц без изменений; осталось 16 исходных
аккаунтов. Все восемь серверных файлов совпадают с проверенным кандидатом,
служба активна, SQLite integrity `ok`, ошибок/quarantine в журнале после
обновления нет. QA-аккаунты и точные служебные записи четырёх проверочных
боёв удалены; посторонние строки и SQL-триггеры сохранены.

После завершения QA подключился обычный игрок и начал свой бой. Его новые
сохранения и штатные изменения аукциона сохранены; текущая БД не
восстанавливалась из резервной копии. Итоговый health-отчёт различает
сохранность данных в момент установки и последующую нормальную активность.
