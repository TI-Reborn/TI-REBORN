# Сжатые пакеты клиента и лаунчер 0.1.10

Для первой установки и крупных обновлений лаунчер может скачать один ZIP
вместо тысяч отдельных ресурсов. В клиенте 2026.10.15.2 опубликованы 6605
файлов общим размером 610 541 094 байта. ZIP содержит 6318 уникальных ресурсов
и занимает 518 942 448 байт. Многие изображения и звуки уже сжаты, поэтому
основной выигрыш — сокращение числа HTTP-запросов, а не кратное сжатие.

В `manifest.json` схемы1 добавлено необязательное поле `archive`:

```json
{
  "size": 518942448,
  "sha256": "1f41ac257d683c78d21e51af46228e5a04df304af7ec32694fde2db5ab5f98f2",
  "filesSha256": "3a088d9163ec585b87cedadb09a1722e2ecb94f66588e2e5249a2dfc01cc7a6d"
}
```

ZIP доступен по существующему immutable URL `/updates/blobs/<sha256>`.
Его записи названы SHA256 ресурсов. Клиент сверяет размер и SHA256 архива,
точный набор записей и размеры, затем распаковывает только нужные ресурсы
в собственный кэш с отдельной проверкой SHA256. Имена из ZIP не используются
как пути установки. Личные `login.ini`, config/autoexec, заметки и панели
не публикуются; существующие seed-настройки сохраняются.

Пакет скачивается, если он не больше суммы отсутствующих ресурсов.
Для 32 и более уникальных ресурсов допускается превышение до25%, чтобы
сэкономить сетевые задержки. Небольшая правка продолжает скачиваться отдельным
blob. Сохранённый проверенный ZIP используется для восстановления без сети.
Обрывы докачиваются с проверкой Content-Range; полностью повреждённый файл
скачивается заново. Отмена не меняет установленный клиент до стадии установки.

`filesSha256` — SHA256 UTF-8 строк, отсортированных по ASCII-пути:
`path + TAB + decimal size + TAB + sha256 + TAB + seed(0/1) + LF`.
Поле связывает ZIP с точными файловыми записями. Старые лаунчеры игнорируют
`archive`; новые поддерживают манифесты без ZIP. Если частичный издатель
перенёс старое поле `archive` в новую версию, несовпавшая привязка отключает
ZIP и сохраняет обычное обновление. Steam продолжает использовать свой
локальный depot без сетевых пакетов.

В стадии установки сначала готовятся все резервные копии, затем записывается
один полный журнал восстановления. После этого копируются ресурсы.
Сбой/отмена восстанавливает прежние файлы и удаляет новые по этому журналу.
Это устраняет повторную сериализацию растущего списка после каждого файла.

## Сборка и публикация

`launcher/build_release.py` создаёт ZIP автоматически. Для полного каталога
релиза с готовыми blobs его можно добавить отдельно:

```powershell
python launcher/build_archive.py PATH_TO_RELEASE
```

После публикации частичного клиентского релиза ZIP следует пересобрать из
актуальных **серверных** blobs, не из установленного пользовательского клиента:

```powershell
python tools/manage_launcher_archive.py inspect --baseline MANIFEST_SHA256 --report inspect.json
python tools/manage_launcher_archive.py prepare --baseline MANIFEST_SHA256 --report prepared.json
python tools/prepare_launcher_publication.py --backup --report preupdate-backup.json
python tools/manage_launcher_archive.py publish --baseline MANIFEST_SHA256 --prepared prepared.json --backup preupdate-backup.json --report published.json
```

Инструмент проверяет точный исходный манифест, исходные blob-хеши, готовый ZIP,
проверенную копию БД и исходного манифеста. Сначала публикуется неизменяемый ZIP,
последним атомарно заменяется манифест. Nginx, игровой код, службы, версия
игрового клиента и файловые записи не меняются. Для отката только этого поля:

```powershell
python tools/manage_launcher_archive.py rollback --baseline PUBLISHED_MANIFEST_SHA256 --prepared prepared.json --backup preupdate-backup.json --report rollback.json
```

Откат требует точного совпадения текущего манифеста с данной публикацией;
живые БД не восстанавливаются, blob сохраняется. Новый EXE публикуется отдельно
через существующие `prepare_launcher_publication.py`,
`run_launcher_update_publication.py` и `verify_published_launcher_update.py`.

## Проверки

Материалы: `reports/launcher-archive-20261016/`.
Python-проверки сборщика и существующих инструментов публикации, тесты
самообновления/путей/Steam/языка/TLS и18 групп проверок ZIP выполнены локально.
Проверки ZIP включают обрыв, ошибочный диапазон, игнорирование Range,
повреждённые байты, лишние/недостающие/повторные записи, обход путей, неверный
SHA256 ресурса, отмену загрузки и откат посреди установки.

`qa/ArchiveAcceptance.csproj` использует настоящий Updater с полным серверным
ZIP: проверяет установленные хеши всех ресурсов, одну загрузку пакета,
повторную проверку без сети, восстановление из ZIP и сохранность настроек.
Режим `hosted` повторяет этот сценарий через доверенный production HTTPS.
Это автоматическая установка ресурсов; вход в аккаунт и интерактивный
графический игровой клиент не входят в эти проверки.
