Базовый suite явно перечисляет проверки в `tools/run_server_checks.py`:
упаковка runtime и отсутствие research-зависимостей; TCP-вход/покупка/перезапуск;
три многопользовательских сценария изоляции, reconnect, экипировки и банка;
очередь survival; прямой обмен; QA-исключения рейтингов; кошельки.
Временные SQLite-базы создаются самими тестами. Это не ручная приёмка настоящими
игровыми клиентами и не проверка действующего хостинга.

## Известные ограничения расширенного suite

`python -m unittest discover -s tests -v` не является зелёным baseline этого снимка.
Пробный полный запуск был прерван после отсутствия продвижения на
`test_battle_loot.BattleLootTests.test_owned_equipment_loses_half_current_on_deposit_only`.
До остановки были ошибки в native/client-фикстурах, deployment-тестах и отдельных
игровых тестах. Полное число проходящих/падающих тестов не установлено.

Полный запуск `test_multi_account` также был прерван на
`test_reversed_handoffs_same_ip_isolation_and_restart` после отсутствия продвижения.
Причина зависания не диагностирована; оно не исправлялось при упаковке исходников.

Отдельно воспроизведена ошибка
`test_multi_account.MultiAccountTests.test_premium_purchase_and_personal_shop_prices`:
`tests/test_multi_account.py:275`, ожидалось `assets.gold == 9990`, получено `10000`.
Та же ошибка подтверждена отдельным запуском в исходном `C:\TIO-emulator`.
Игровое поведение или ожидание теста нужно разобрать отдельной задачей;
искусственно исправлять результат ради зелёного suite нельзя.

Для тематического запуска (из корня, переносимо между PowerShell и bash):

```text
python -m unittest discover -s tests -p test_rating_visibility.py -v
python -m unittest discover -s tests -p test_player_trade.py -v
```

Часть исторических тестов требует материалов `evidence/`, `reports/`, сайта `web/`,
лаунчера, клиентских DLL или research-библиотек, которые не включены в серверный handoff.
Не копируйте весь рабочий каталог ради этих тестов: согласуйте конкретные очищенные
фикстуры с владельцем. Базовый CI — smoke suite, а не заявление о прохождении всех тестов.

## Границы аудита

Передача включает только исходники, шаблоны и явно разрешённые runtime-ресурсы.
Проверялись запрещённые пути/расширения, SQLite-сигнатура, приватные ключи, типовые
GitHub/AWS-токены и URL с паролями. Дополнительно просмотрены найденные литералы
паролей: они относятся к тестовым значениям и генерируемым временным данным.
Проверка шаблонами не доказывает отсутствие любого возможного секрета.
Production-база, ключи и `.env` не копировались; сравнение с production-кодом не выполнялось.

GitHub CI использует Python 3.12 на Ubuntu; его фактический результат нужно проверять
в Actions. Локальный PASS на Windows не заменяет результат CI.
