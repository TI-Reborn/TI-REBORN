## Как устроено

- **Файлы.** `tools/build_hd_map_textures.py GODOT_ASSETS CLIENT OUT` берёт
  текущий лист клиента и заменяет в нём только кадры из `hd_index.json`.
  Кадр из HD-листа (×4) уменьшается до родного прямоугольника с
  предумноженной альфой. Остальные кадры остаются клиентскими. Размер листа
  не меняется: рендер адресует кадры в родных пикселях. Результат
  `base/hd/setting/<rel>.hd` — это PNG.
- **Почему `.hd`.** Клиент ищет текстуры по имени файла во всех подпапках
  (`ti.exe` 0x6b0f7c, первая найденная папка выигрывает). Копия с тем же
  именем подменила бы оригинал и в «Оригинальном» интерфейсе. Имена с
  суффиксом `.hd` поиск никогда не находит.
- **Перехват.** Все текстуры тайлов читаются одним вызовом
  `TMemoryStream.LoadFromFile` в `ti.exe` (0x6b12f9, EAX=stream,
  EDX=путь). Лаунчер 0.1.48 (`NativeHdMapTextures`) в режиме «Новый» ставит
  туда вызов адаптера (`tools/build_native_hd_map_textures.py`,
  `Assets/native-hd-map-textures.json`). Адаптер превращает
  `…\setting\<rel>` в `…\hd\setting\<rel>.hd`. Если такой файл есть
  (`GetFileAttributesW`), он и загружается, иначе путь остаётся прежним.
  `ti.exe` закреплён по SHA, silver.dll не затронут, так что участки Silver
  для других адаптеров не меняются.
