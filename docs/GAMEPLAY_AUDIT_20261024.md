- No single shared metadata-loading failure was found. SE outcome handling, Exo coverage, drill capacity and selection routing have separate concrete causes. Injection and blocker metadata implement different effects despite their shared native medkit presentation class.

## Character retirement and migration

`character_revisions` is an additive table. Legacy characters, owner keys, mappings, credentials, wallets, item rows and immutable transaction receipts are retained. Deletion adds an archive marker; creation in a freed slot creates a fresh generation key. Archived character names stay reserved, preventing an old public name/history from silently attaching to a new save. Archived saves are excluded from public rankings and public name resolution. Subscription and anti-farming identity continue to resolve to the same authenticated login.

Deletion refuses retained/persisted battles, unsettled results, active travel/prison, clan membership, active parties/contracts, auction/loan obligations and private shop offers. The player must resolve these normally. It does not silently abandon a clan, return another player's loan, erase market history or move their property. No automatic restoration UI is introduced. Database rollback on failure is covered; restoring an old full production database over newer progress is never an acceptable rollback.

The existing native dismissal service retains its configured 48-hour timer. This audit fixes eligibility and feedback; it does not silently convert delayed dismissal into immediate destruction or dismiss any existing player fighter.
