# Проверка урона улучшенного оружия, 17.11.2026

Сервер учитывает реальное улучшение предмета (`unknown_bytes_03[0]`) при
обычной атаке. Отображаемый уровень (`unknown_bytes_02[0]`) не является
источником урона. Из 32 улучшаемых видов оружия 31 проходит проверку;
Перфоратор (322) отклоняется до расчёта урона с `Ammo rule missing`.
В его записи каталога `weaponAttack=Bullet`, но `ammo_id=null`.
Не назначали ему боеприпас предположительно и не меняли боевые правила.

## Формула

Эффективное улучшение равно минимуму реального улучшения и ограничения
по уровню наёмника:

| Уровень наёмника | Максимальный эффект |
| --- | --- |
| 1–3 | +3 |
| 4–6 | +10 |
| 7–10 | +15 |
| 11–15 | +20 |
| 16 и выше | +25 |

Бонус к обоим концам базового диапазона: `n`, если `n <= 2`, иначе `2*n-2`.
Следовательно, +1 даёт 1, +2 — 2, +3 — 4, +10 — 18, +25 — 48.
Далее применяются дальность, владение оружием, попадания/критические удары,
другие боевые бонусы и броня. Поэтому бонус не равен дополнительным снятым HP.
Округление может скрыть небольшую прибавку в отдельном выстреле.
Подствольная граната Грозы использует собственный урон без улучшения автомата.

Пример реальных серверных атак P90: наёмник уровня 16, владение 35,
дистанция 1, цель без брони, все пули попали, критических ударов нет.

| Улучшение | Снимаемые HP, минимум–максимум |
| --- | --- |
| +0 | 34–51 |
| +1 | 34–51 |
| +2 | 35–52 |
| +3 | 37–54 |
| +5 | 40–57 |
| +10 | 49–66 |
| +15 | 57–74 |
| +20 | 66–83 |
| +25 | 74–91 |

## Проверки

Добавлен `tests/test_weapon_enhancement_damage.py`: 7 тестовых методов,
5179 успешных атак и отдельно ожидаемое падение для Перфоратора.
Матрица содержит 31 вид оружия × 26 уровней улучшения × оба конца урона;
все уровни улучшения для четырёх младших ограничений; дальность и броню
для пяти разных типов оружия; подмену отображаемого уровня; критические
удары P90 и подствольную гранату Грозы.

Проверяются изменение HP в `BattleField` и результат `4B`, передаваемый
клиенту. Для дистанционного округления используется существующий отдельно
тестируемый алгоритм каталога; ожидаемый бонус улучшения вычисляется
независимо от `EnhancementRules.bonus`. Атаки выполняются между двумя
владельцами в общей серверной модели боя, без подключения графических клиентов.

На VPS тесты импортируют непосредственно `/opt/tio-emulator/tio`,
используют опубликованные config/evidence и временные тестовые базы.
Хеши 10 ключевых исходников/каталогов совпали с локальными; проверено их
сохранение после тестов. База игроков, служба и публикация клиента не менялись.

Локально дополнительно выполнен 81 смежный тест: 4 failures и 3 errors
(два errors относятся к подслучаям одного теста XML). Причины:

- Старые тесты требований экипировки ожидают базовый уровень 1 вместо
  текущего 4 у выбранных предметов.
- Список навыков и счётчик оружия не учитывают добавленные ID 318, 320,
  5001, 5013.
- Проверка XML ожидает `patk` у мин 318 и 320, где такого узла нет.
- Сетевой тест ожидает старый набор ответов без дополнительных F7/F9/FB.

Первый расширенный запуск на VPS: 86 методов, 4 failures, 2 errors,
1 expected failure. Дополнительное отличие среды: инструмент
`tools.normalize_weapon_xml` на production не установлен, поэтому его
тест не импортируется. Падения не выдаются за успешные проверки.

Итоговая матрица из 7 методов прошла локально и на VPS: 6 успешных методов,
1 expected failure (Перфоратор), 5179 успешных атак в каждом запуске.
`python tools/run_server_checks.py`: 724 теста, OK.
`python -m server --check` прошёл. `tools/check_handoff.py` отсутствует.
Логи находятся в `reports/weapon-enhancement-20261117/`.

## Ограничения

Перфоратор остаётся отдельным обнаруженным дефектом: формулу улучшения для
него через успешную атаку подтвердить невозможно, пока нет правила расхода
боеприпасов. Реальные графические клиенты и сетевой бой на публичном сервере
в рамках этой проверки не запускались. Изменены только тесты и документация.
