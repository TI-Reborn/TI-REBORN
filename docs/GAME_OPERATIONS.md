# Общие игровые операции — приоритет 3

Первый рабочий этап от 15 октября 2026: общая серверная модель команд,
проверок и результатов, подключённая к городским услугам. Идея взята из
организации `Shared` другого TIO-проекта; реализация написана для нашего
авторитетного Python-сервера. Редактор карт пропущен по указанию пользователя.

## Что подключено

| Операция | Входы | Существующие правила |
| --- | --- | --- |
| Переименование | сайт, Services V2, штатная команда игрового клиента | цена 3000 кредитов при изменении имени, прежние ограничения имён |
| Отложенное увольнение | сайт, Services V2, пакет игрового клиента | прежняя задержка 48 часов и ограничения на основного бойца |
| Получение награды после увольнения собаки | сайт, Services V2 | прежняя однократная выдача |
| Покупка клановых складских улучшений | сайт | личная оплата, общее состояние клана |
| Запрос смены аватара | сайт, Services V2 | остаётся отключён действующим правилом |

Механизм одинаков для нескольких реальных аккаунтов. Аккаунт/слот разрешает
авторизованный адаптер; цена и доступность вычисляются сервером. Клиенту
нельзя передать внутреннего владельца, разрешающий флаг или стоимость.

## Устройство

`server/game_operations.py` содержит неизменяемые `OperationCommand`,
`OperationSpec`, `OperationResult` и реестр `OperationRegistry`.
Подготовленная команда хранит снимок аргументов и ID запроса. Даже после
предварительной проверки выполнение повторно проверяет аргументы и текущий
контекст: старое разрешение не даёт права выполнить действие позже.

`server/service_operations.py` задаёт один реестр услуг. Из него получаются
поля HTTP-контрактов. Внутренняя команда с текстом `/changename` отсутствует
в HTTP-схемах. Адаптеры `city_services`, `services_v2`, `services_runtime`
передают команды этому реестру вместо отдельных ветвей диспетчеризации.

Контекст требует текущую открытую транзакцию именно нужной SQLite и повторно
проверяет владельца, город, путь, бой и тюрьму. Внешний адаптер сохраняет
существующую общую блокировку сервера. Доменные функции и их durable receipts
остаются источником правил и защиты от повторного списания.

Результат содержит связавшую его команду, неизменяемые данные, признак повтора
и затронутых владельцев. Ошибка бизнес-правила возвращается в прежнем формате;
неверный результат обработчика считается программной ошибкой. Списание,
изменение персонажа, квитанции и подготовка ответа входят в одну транзакцию.
Сбой формирования ответа откатывает их вместе. Обновление активных сессий
городского HTTP-адаптера выполняется после commit.

Новые таблицы и миграция сохранений не требуются. Баланс, протокол и интерфейс
игры этим этапом не меняются. Боевые команды используют свои существующие
обработчики. [Общие банковские операции](BANK_OPERATIONS.md)
и [операции торговли и аукционов](TRADE_OPERATIONS.md) установлены следующей
общей сборкой 15 октября 2026 после явного запроса пользователя.

## Проверки и воспроизведение

Локальное дерево оказалось неполным относительно хостинга. Для проверки
сохранён read-only снимок исходников действующего сервера (без player DB и
секретной конфигурации). В него накладываются только пять изменённых файлов.
Production `services_v2.py`, отсутствовавший локально, восстановлен из этого
снимка перед изменением. Историческое ожидание теста исправлено с 30 Gold
на действовавшие до этого этапа 3000 кредитов; это не изменение цены.

```powershell
python -X utf8 tools/check_game_operations.py
```

40 проверок покрывают неизменяемость, повторную проверку контекста,
конкурентную отправку, scoped ID запроса, изоляцию аккаунтов, rollback,
связку сайта с игровым адаптером и общий склад двух членов клана.

`tools/verify_game_operations_hosted.py` создаёт два случайных QA-аккаунта из
зарезервированного пространства, проверяет их исключение из рейтингов и
использует обычные TLS-входы и запросы карты. Стартовые деньги не подменяются.
Далее проверяются платные переименования через протокол и HTTP, уникальность
имён между аккаунтами, отсутствие повторного списания, отказы и reconnect.
Секреты остаются в памяти. Очистка удаляет только exact-owned QA-записи,
проверяет неизменность всех остальных строк и восстановление SQL-триггеров
в той же транзакции. Это протокольная проверка; графический клиент ею
не проверяется.

## Поставка первого этапа

Изменены ровно пять серверных файлов из `patch-manifest.json`. Инструмент
`tools/deploy_game_operations_remote.py` сверяет весь исходный runtime-снимок
и hashes кандидата, по умолчанию отказывает при подключённых игроках,
всегда отказывает при сохранённом бое,
проверяет кандидат отдельно, сохраняет код/config и две проверенные SQLite
копии. Затем заменяет только код и перезапускает `tio-server`.
При ошибке возвращает прежний код, сохраняя текущую удалённую БД.
Локальные сохранения на сервер не загружаются.

Резервная копия этой поставки:
`/root/tio-before-game-operations-20261015-81f3`.
До перезапуска сохранено содержимое всех 167 таблиц, после него изменений
таблиц не обнаружено. Служба активна, SQLite integrity `ok`.
Доказательства находятся в `reports/game-operations-20261015/`:
`automated-checks.json`, `patch-manifest.json`, `deployment.json`,
`hosted-verification.json`, `hosted-health-final.json`.

Hosted-проверка прошла на двух одновременных TLS-аккаунтах: каждый потратил
ровно свои стартовые 3000 кредитов на переименование, коллизия общего имени
отклонена без списания, HTTP-повтор вернул ту же квитанцию, reconnect показал
новые имена. Протестированы также бесплатный запрос прежнего имени,
отключённый аватар, запрет увольнения основного бойца, лишний `owner` и
неавторизованный HTTP-запрос. Оба QA-аккаунта были исключены из рейтингов
до входа и полностью удалены вместе с квитанциями после проверки.
Осталось исходное число аккаунтов — 14; данные прежних игроков сохранились.

Первый запуск hosted-сценария остановился до списания: новый legacy-персонаж
ещё не имел сохранённой городской позиции. Его fixtures полностью очищены.
Сценарий исправлен обычным кликом текущего города через пакет карты `1B`,
без SQL-подмены позиции. Отчёт первого запуска сохранён отдельно как
`hosted-verification-attempt1.json`.
