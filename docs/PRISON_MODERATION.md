# Назначение Prison доверенным оператором

`tools/moderate_prison.py` запускается локально оператором с доступом к
существующей SQLite БД. Это административный интерфейс, а не публичный
игровой запрос. Автоматических наказаний и клиентского opcode нет.

По документации размещения рабочая БД находится в
`/var/lib/tio-server/reservation.sqlite3`, код — `/opt/tio-emulator`.
Оператор сначала проверяет фактическую конфигурацию и актуальную резервную
копию. Путь обязателен: команда не выбирает локальную/рабочую БД по умолчанию
и не создаёт отсутствующую БД.

Пример **для ручного запуска оператором**, после замены публичного имени и
ключа конкретного решения:

```sh
cd /opt/tio-emulator
.venv/bin/python -m tools.moderate_prison \
  --database /var/lib/tio-server/reservation.sqlite3 \
  --character PUBLIC_CHARACTER_NAME \
  --seconds 3600 \
  --operation moderation:case123
```

Допустимое публичное имя соответствует существующим правилам персонажей:
3–16 ASCII букв/цифр, первая буква. Регистр при поиске не важен. Поиск
`character_identity.owner_for_name` определяет именно сохранение выбранного
персонажа; дополнительные слоты одного аккаунта остаются независимыми.
Не передавайте логин, пароль, session token или внутренний owner alias.

Срок — 1–31536000 **онлайн-секунд**, включая уже оставшийся срок. Работа
выполняется существующим `world_completion.sentence` внутри единой
`BEGIN IMMEDIATE` транзакции. Активный/карантинный battle checkpoint или
ожидающий settlement этого персонажа блокирует новое назначение. Сначала
нужно штатно завершить или восстановить бой. Путь в дороге отменяется;
предыдущее место сохраняется для возврата после отбытия срока. Офлайн-время
не уменьшает срок; heartbeat сервера ведёт онлайн-отсчёт.

`--operation` — постоянный ключ решения, 1–160 символов `A-Z a-z 0-9 _ . : -`.
Повтор с теми же персонажем/сроком возвращает `replayed`, без повторного
начисления. Повтор ключа с другим персонажем или сроком даёт
`conflicting_operation` и откатывает изменения. Для нового отдельного
решения нужен новый ключ. Уже отбытые секунды не начисляются снова при retry.

Команда выводит одну JSON-строку только с `character`, `remaining`, `replay`,
`status`. Логин, внутренний owner, ключ операции и heartbeat token не
выводятся. Код выхода 0 — commit/replay, 2 — отказ; ошибки SQLite и аргументы
не печатаются целиком. Статусы отказа: `invalid_request`,
`database_unavailable`, `character_not_found`, `battle_pending`,
`conflicting_operation`, `sentence_limit`, `operation_rejected`.

Этот инструмент не подключается к VPS и сам не проверяет размещение.
Положительные назначения на рабочем сервере при подготовке не выполнялись.
