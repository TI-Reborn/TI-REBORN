# Казарма, склад и HD-предметы — клиент 2026.10.25.2

Поставка опубликована и проверена на хостинге. Источник — фактически опубликованный клиент
2026.10.24.2, Silver SHA256
`28f33ff6a920182eeb7a81b9d3c30853081f3f52c7d505da15b54de97c01b2ad`.
PR #31 содержит спецификацию A2 и художественный конвейер; исполняемая раскладка
реализована отдельно в этой поставке.

## Состав

- `deploy/client_barracks_a2.py`: чистый трансформер закреплённого Silver,
  исходные native-контролы, увеличенная центральная модель, экипировка и рюкзак
  слева, склад/навыки справа, пять подписанных вкладок и отдельная раскладка
  входящей/исходящей почты. На малом логическом холсте сохраняется штатный GUI.
- `deploy/client_item_icon_render.py`: отдельный scoped-рендер предметов и
  квадратная сетка 72 px. Нативные обработчики и данные предметов сохранены.
  Размеры временной графической метаинформации восстанавливаются после рисунка.
- `deploy/client_item_icons_hd.py`: замена только выбранных полей `image` и
  перенос четырёх уже действующих серверных признаков `stackable` в стартовый
  клиентский каталог. Параметры урона, AP, веса и прочие правила не меняются.
- 101 новая обычная иконка 64×32; 146 отдельных HD-ресурсов 512×512.
  У HD-ресурсов уникальные имена: клиентский кэш различает изображения по basename.
- Изменяются `silver.dll`, клиентский XML предметов и только `image` у 101 записи
  серверного XML. `ti.exe`, launcher, серверный Python и конфигурация не меняются.

Добавлены четыре увеличенные карточки с именем, уровнем, рейтингом, силуэтом
и HP; центральная полоса HP и подиум; вертикальные слоты брони, рюкзак 4×3,
пять вкладок с иконками. Цель рендера модели увеличена до 1024² с откатом при
ошибке выделения ресурса. Модули cards, skin, bag, navigation и social отделяют
рисование, геометрию, обработку выбора и дополнительные окна.

Раскладка повторяет композицию присланного A2. Пиксельное совпадение декоративных
деталей не заявляется: сохранены штатные шрифты, служебные переключатели склада,
кнопки рюкзака и фактическая игровая вместимость. Отображение полного комплекта
брони и все возможные состояния кланов требуют отдельной визуальной приёмки.

## Проверки

Тематические unittest: 29 тестов. Серверный переносимый набор на экспорте PR #31:
659 тестов, OK; `check_handoff.py` — 2397 файлов, 0 замечаний; preflight — OK.
В корневом рабочем каталоге два CI-скрипта отсутствуют, поэтому они запущены
из подготовленного исходного экспорта, с копиями новых модулей и тестов.

Native-проверки исполняют x86-код: раскладка в двух адресах загрузки и пяти
размерах, продвижение/перенос строки сетки, четыре области callback предмета,
ABI рендера, восстановление метаданных, почтовая раскладка, составная графика,
идемпотентность и отказ на изменённом образе.

Два собственных исключённых из рейтингов аккаунта вошли настоящим клиентом
через действующий TLS-хостинг последовательно. При Full HD / UI 100% проверены
собственные склады/счётчики, получение оружия со склада двойным нажатием,
снятие оружия, перенос из рюкзака на склад, подсказки, контекстное меню,
вкладка навыков, входящая/исходящая почта. До публикации исполняемый кандидат
проверялся в памяти только собственного QA-клиента. Пользовательский клиент
не изменялся и не управлялся. Повторная пара исключённых QA-владельцев удалена.
Оба аккаунта вошли уже с опубликованной DLL и показали независимые склады
и количества 3 и 7 Upgrade Kit. Состояние рендера 1024² подтверждено в процессе.

Дополнительно проверены UI 125%, четыре бойца включая собаку, двенадцать
предметов в рюкзаке, компактный счётчик склада, размещение клана и альянса.
Графическая проверка масштабов 150/200%, QHD, реального клана, боя,
поворота модели и применение ремонта/улучшения новой поставкой ещё не завершена.
Эмуляция раскладки не заменяет эти проверки настоящими клиентами.

Клиент 2026.10.25.2 добавляет количество стака в квадратной ячейке склада.
Штатное количество рюкзака сохранено. Настоящим клиентом подтверждён перенос
трёх Upgrade Kit в рюкзак и возврат на склад через контекстное меню; значения
стака и общего счётчика обновились. Перенос перетаскиванием отдельно не принят.
