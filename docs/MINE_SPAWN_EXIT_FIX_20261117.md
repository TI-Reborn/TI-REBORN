# Исправление поражения после первого шага в шахте

Позднейшее уточнение владельца отменило автоматический выход при возвращении
к входу: актуальные правила и публикация описаны в
[MINE_MENU_EXIT_20261117.md](MINE_MENU_EXIT_20261117.md). Ниже сохранён отчёт
о промежуточном исправлении.

На хостинге подтверждены два завершения шахты с поражением в 16:14:48 и
16:15:26 UTC 17.11.2026. В обоих отчётах 0 нанесённого/полученного урона,
0 убийств и 0 смертей; извлечение кристаллов также равно 0. Причиной была
автоматическая обработка выхода, а не расчёт урона оружия.

Входная площадка входит в набор клеток выхода. Обработчик принимал любое
движение внутри этой площадки за выход. Кроме того, пустой бур позволял
автоматически завершить бой после другого действия на площадке.

Исправлены две точки:

- `server/team_arena.py`: перед перемещением запоминается, находился ли
  весь живой отряд в зоне выхода. Движение запускает выход только при
  переходе из шахты в эту зону.
- `server/mine_arena.py`: автоматическая выгрузка без перехода требует
  положительного количества кристаллов в буре. Пустой бур не вызывает
  поражение при первом шаге или окончании хода.

Возвращение из шахты в зону выхода без кристаллов по-прежнему завершает
бой с поражением. Явный Esc с пустым буром также остаётся разрешённым
при выполнении правил отсутствия противника и блокировки выхода.
Расчёт одной атаки за клик сохранён.

## Проверки

`tests/test_mine_spawn_exit.py` воспроизводит обработку настоящих пакетов
движения через общий сервер боя и временную SQLite:

- первый шаг добытчика внутри входной площадки;
- тот же шаг с пустым буром;
- завершение хода с пустым буром;
- шаг рейдера внутри входа после пяти ходов блокировки;
- выход из стартовой зоны и намеренное возвращение в неё.

Три сценария добытчика воспроизводили ошибку до исправления. После
исправления все 5 сценариев прошли. На хостинге в изолированной копии
опубликованного окружения прошли 57 тематических тестов, включая выходы,
общую шахту и ранее согласованные пороги кристаллов. Общий набор из
724 серверных тестов также прошёл. Новый модуль добавлен в обязательный
набор `tools/run_server_checks.py`.
Повторный запуск расширенного обязательного набора: 729 тестов, OK.

Публикация: `tools/deploy_mine_spawn_exit_20261117.py`, только два серверных
файла, существующие backup и проверки отсутствия боёв/незавершённых расчётов.
Логи: `reports/mine-spawn-exit-20261117/`.

Сценарий `tools/verify_mine_spawn_exit_hosted_20261117.py` предназначен
для проверки через публичный TLS двумя временными аккаунтами в шахтах
11–15 и 16–20. Аккаунты используют исключённое из рейтингов пространство
QA. Проверка не подменяет графические игровые клиенты.

## Результат публикации

Исправление установлено после завершения активного боя. Backup:
`/root/tio-before-game-operations-mine-spawn-exit-20261117-20261117`.
Обе замены файлов проверены по SHA256; все 175 таблиц сохранились до
перезапуска, защищённые данные игроков совпали после запуска. 93 аккаунта,
SQLite integrity_check — OK.

Публичная TLS-проверка завершилась успешно на двух временных аккаунтах:
шахты 11–15 и 16–20, вход, первый шаг внутри стартовой площадки, отсутствие
пакета поражения, сохранение HP и того же активного боя, расход ОД на шаг.
После проверки оба отряда штатно вышли через выход карты; временные аккаунты
удалены после подтверждения отсоединения игровых сессий повторной авторизацией.
При первом запуске проверочного сценария лишний пакет загрузки после возврата
в город был отклонён; сценарий исправлен и полностью повторён успешно.

Для сохранения свободного места закрытый системный журнал сжат без потери
данных с проверкой SHA256; три завершённые временные validation-копии от
17.10.2026 сохранены в `/root/completed-validation-archives-20261117`.
Проверены хеши всех файлов перед удалением распакованных копий; рабочий
каталог сервера и резервные базы игроков не затронуты.
