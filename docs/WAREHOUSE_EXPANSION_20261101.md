# Расширение личного склада через «Сервисы», 2026-11-01

В проверенных `base/services.cfg` установленного клиента 2017 года и архива
`reports/client-version-research/archive-20231004` найдены только два пакета
личного склада: service ID 1, уровни 1/2, общая прибавка 8/16 мест.
ID 3/4 относятся к клановому складу/сейфу, а не к личному складу.
Это ограниченная проверка доступных версий, не утверждение обо всех выпусках игры.

По явному решению владельца добавлены новые серверные уровни 3–6:

| Уровень | Прибавка к базе 32 | Общая ёмкость | Цена уровня, кредиты |
| --- | ---: | ---: | ---: |
| 1 | 8 | 40 | 5 000 |
| 2 | 16 | 48 | 15 000 |
| 3 | 32 | 64 | 30 000 |
| 4 | 64 | 96 | 60 000 |
| 5 | 128 | 160 | 120 000 |
| 6 | 256 | 288 | 240 000 |

Цена оплачивается последовательно за каждый уровень. Прибавки не суммируются.
Ранее купленные уровни сохраняются. Новые таблицы и миграции не нужны.

Серверные runtime-правки — каталог `tio/services.py:OFFERS[1]` и его XML-формат.
Из него уже строятся XML, B1/03-каталог следующей покупки, B1/01-состояние,
стоимость, проверка последовательности и авторитетная ёмкость склада.
`BEGIN IMMEDIATE` сохраняет атомарность денег/уровня и повторов запросов.
Личный склад остаётся общим между городами и входами в шахты для персонажа.

в поставку он не включён.

После сообщения пользователя о «дополнительные слоты: 0» ошибка воспроизведена
в реальном QA-клиенте. Нативная таблица содержала шесть нулевых power.
Сервер ранее выводил `power` только атрибутом level, но `0x680974` читает карту
`node+8`, заполняемую дочерними записями `key/val`. Добавлен штатный формат
`<value key="power" val="32"/>`; старый атрибут сохранён для существующих
адаптеров. Проверка этого контракта сначала падала, после исправления проходит.

Дополнительно опубликован клиент 2026.11.01.1: описание сервиса 1 теперь
показывает разницу соседних total power — 8/8/16/32/64/128, сохраняя правила
вместимости. Новый `deploy/client_warehouse_service_description.py` меняет
только вызов `0x848ead`, три поля геометрии PE и добавляет 4096 байт PIC-кода.
Другие сервисы используют исходный обработчик. Для старого/нулевого XML есть
fallback, скомпилированный из того же серверного каталога. При добавлении новых
уровней этот fallback требует пересборки клиента.

## Проверки и поставка

Регрессии написаны до изменения каталога: новые покупки/XML/49-й слот сначала
не проходили. После изменения проходят тесты последовательных цен, отказов,
конкурентного повтора, изоляции аккаунтов и сохранения склада между городами.

Автоматические проверки, поставка, hosted TCP и графический клиент фиксируются
отдельными JSON в `reports/warehouse-expansion-20261101`.
Hosted QA использует только случайные исключённые логины `qt<8 hex>[ab]`;
проверяющий скрипт очищает исключительно принадлежащие им строки.

Итог: 37 целевых серверных тестов и preflight проходят; пять native-тестов
описания проходят. Широкий `run_server_checks.py` на копии хостинга выполнил
651 тест: 17 падений и 13 ошибок. Все эти 30 случаев отдельно воспроизведены
со старым двухуровневым каталогом, с идентичными сообщениями; они не исправлены
этой поставкой. Это не полностью зелёный широкий suite.

Два TLS protocol-клиента купили все шесть уровней, проверили повтор без
списания, запрет пропуска уровня, 49-й предмет и переподключение. После
исправления XML два настоящих опубликованных клиента одновременно вошли;
их нативные таблицы содержали корректные power всех уровней. В GUI второго
аккаунта показаны 8/16/32 дополнительных слота для следующих уровней 2/3/4;
кнопками куплены уровни 2/3, баланс уменьшился на 45 000, ёмкость стала 64.
Первый аккаунт сохранил ёмкость 288 и прежний баланс. Последующее TLS
переподключение подтвердило сохранённые уровни 6/3. GUI-покупки 4–6 и
графическое повторное переподключение отдельно не проверялись.
