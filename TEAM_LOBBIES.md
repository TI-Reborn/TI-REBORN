# Командные лобби — экспериментальное обновление

Требуется multi_account = true. Существующий сервер на VPS этим файлом не изменяется.

## Правила

- «Создать» в командном режиме создаёт команду на 2 игрока, в «Стенке» — на 4.
- Остальные игроки присоединяются, затем нажимают «Готов». При изменении состава готовность сбрасывается.
- В оригинальном клиенте у капитана вместо отдельного «Готов» кнопка «Начать»: она подтверждает его готовность и запускает поиск, если готовы остальные.
- Боты добавляются только при «Начать». В 2×2 один лидер получает одного бота; в 4×4 один лидер получает трёх, два человека — двух, три — одного. Правило одинаково для обеих команд.
- Нужна другая команда с живым игроком. Полностью искусственный противник по таймеру не создаётся.
- Подбор использует одинаковый режим, диапазон уровней и число бойцов. В «Стенке» участвует первый выбранный боец каждого игрока.
- Боты временно копируют характеристики и снаряжение капитана, управляются существующим ИИ. Они не создают аккаунты и не изменяют его инвентарь.
- Один бой и поле общие для обеих команд; сохранения людей адресуются отдельно. Выход во время боя считается поражением; загрузка всех людей ограничена 60 секундами.

## Источники и границы восстановления

[Руководство Total Influence, LVI, страницы 15–16](https://ti.ggeek.ru/files/TIO_manual.pdf): готовность участников, запуск капитаном, подбор по уровневому диапазону; для «Стенки» — группы из четырёх и первый выбранный наёмник. Оригинальная адаптация количества наёмников в командном подборе пока не восстановлена: здесь требуется точное совпадение. Дополнение ботами — согласованное временное правило проекта.

Штатные команды подтверждены локальными исследованиями в ARENA.md: C8/2B создание, 2C готовность, 2E старт, 2A/01 выход. BA/04 получает ID второй таблицы списка. Разметка списка и переход из этой таблицы в общее лобби требуют проверки оригинальными клиентами. Не следует считать наличие автоматических тестов подтверждением работы всех кнопок.

## Проверка двумя настоящими клиентами

1. Войти разными аккаунтами, выбрать здоровые отряды одинакового диапазона уровней.
2. Каждому создать отдельную «Стенку» и нажать «Начать». Первый должен ждать второго; затем в одном бою должны оказаться два человека и шесть ботов.
3. Проверить видимость действий другого игрока, ходы ботов, завершение боя и отдельные награды.
4. Проверить командный режим: по одному человеку и одному боту с каждой стороны.
5. Проверить присоединение второго человека в существующее лобби, отказ старта до «Готов», выход и повторный вход. Полные команды не получают ботов.
6. После выхода обоих перезапустить службу и проверить деньги, отряды и инвентарь.

Обновления чужих действий передаются снимками видимых бойцов; плавность анимаций и экран результатов требуют проверки в клиенте. VPS-нагрузка и полные бои оригинальными клиентами пока не проверены.

## Установка на существующий VPS

Закрыть оба клиента. Windows PowerShell:

```powershell
scp C:\TIO-emulator\data\tio-team-lobbies.tar.gz root@185.184.42.88:/root/
```

В SSH выполнить блок целиком. Он сохраняет базу и предыдущий код, конфигурацию не заменяет:

```bash
(
set -e
test -f /root/tio-team-lobbies.tar.gz
test ! -e /root/tio-before-team-lobbies.tar.gz
runuser -u tio -- /opt/tio-emulator/.venv/bin/python /opt/tio-emulator/deploy/scheduled_backup.py --source /var/lib/tio-server/reservation.sqlite3 --directory /var/backups/tio-server --tag pre-update
tar --exclude=.venv --exclude=__pycache__ -czf /root/tio-before-team-lobbies.tar.gz -C /opt/tio-emulator .
systemctl stop tio-server
tar -xzf /root/tio-team-lobbies.tar.gz -C /opt/tio-emulator --no-same-owner
cd /opt/tio-emulator
runuser -u tio -- .venv/bin/python -m server --config /etc/tio-server/server.toml --check
systemctl start tio-server
sleep 2
systemctl status tio-server --no-pager -l
journalctl -u tio-server -n 25 --no-pager
)
```

Порты остаются TCP 28512 и 28513. База остаётся /var/lib/tio-server/reservation.sqlite3; архив её не содержит. Миграция и установка зависимостей не требуются.

Если проверка или запуск завершились ошибкой, сохранить вывод и восстановить код:

```bash
systemctl stop tio-server
tar -xzf /root/tio-before-team-lobbies.tar.gz -C /opt/tio-emulator --no-same-owner
systemctl start tio-server
```

Откат кода не откатывает результаты уже сыгранных боёв. Новые модули останутся на диске, но старый сервер их не импортирует. Для наблюдения: journalctl -u tio-server -f; события team_lobby_joined, team_search_started, team_match_created и team_match_settled.
