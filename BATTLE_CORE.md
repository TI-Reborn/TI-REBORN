# Переподключение, боевой расчёт и командный чат

Обновление от 29 сентября 2026 года. Установлено на основном многопользовательском сервере `185.184.42.88`, служба `tio-server`. Это реализация ближайшего пакета из [аудита руководства](GAME_MANUAL_AUDIT.md), а не завершение всех оставшихся боевых механик.

## Что теперь работает

| Область | Поведение |
| --- | --- |
| Возврат в общий бой | После обнаружения разрыва соединения аккаунту даётся 180 секунд для повторного входа. Сервер возвращает тот же бой, карту, идентификаторы бойцов, текущие HP, ОД, инвентарь, умения и актуальную видимость. Новый персонаж не создаётся. |
| Отключившийся участник | Остаётся на поле и может получать урон. Остальные игроки продолжают бой. Список участников получает признак отсутствия связи. Очереди сообщений отключившемуся не накапливаются. |
| Ход и повторный вход | Время отключившегося участника сокращается; при своевременном возврате восстанавливается исходный абсолютный срок текущего хода. Повторный вход не даёт новый полный ход и не возвращает потраченные ОД. Завершённый ход не возобновляется. |
| Загрузка после входа | На загрузку сцены отводится 30 секунд. До подтверждения загрузки боевые действия отклоняются. Состояние берётся из общего серверного поля; данные клиента не принимаются за сохранение. |
| Завершение боя без связи | Возвращается сцена и уже сохранённый результат. Награды, опыт и остальные результаты не начисляются повторно. После истечения 180 секунд незавершённое участие оформляется как выход. |
| Личный PvE | В пределах того же срока восстанавливаются текущий экземпляр шахты/другого личного боя, вещи и известные залежи. Личный PvE без подключённого клиента приостанавливается; в общем PvP такой паузы нет. |
| Человеческие криты | Подключены базовая вероятность оружия и бонус изученного критического перка. Критическая пуля наносит двойной сырой урон; результат проходит обычные броню, износ, статистику и достижения. |
| Очереди | Попадание и крит проверяются отдельно для каждого снаряда по числу из каталога. Патроны и ОД расходуются один раз на атаку. Полный диапазон урона оружия относится ко всей очереди: он не умножается на число патронов. |
| M60 / Minigun | Атака поражает живых бойцов на линии огня, включая союзников. Дальность, дистанционный урон и перекрытие линии препятствием учитываются для каждой цели. Изменения всех целей и вещей фиксируются одним действием. |
| Общий боевой чат | Канал 3 доставляется остальным настоящим участникам этого боя. |
| Командный чат | Канал 4 доставляется только союзникам в этом же бою. Состав и сторона определяются сервером. Городской посторонний не может читать или писать в эти каналы. |
| Защита чата | Имя отправителя берётся из аутентифицированной сессии. Сохраняется проверка текста: до 200 символов, корректный UTF-16, без управляющих символов. Ограничение — 5 сообщений за 5 секунд на участника. Повторный вход не сбрасывает этот боевой лимит. |

Отправитель уже видит свою строку локально в оригинальном клиенте, поэтому сервер не присылает ему дубликат. История сообщений за время отсутствия не воспроизводится. Это проверено по пути отправки в DLL и сетевым сценариям; визуальная проверка самим клиентом остаётся отдельно.

## Правила эмулятора и оставшиеся ограничения

180 секунд на возврат и 30 секунд на загрузку — явно выбранные серверные правила. Это не восстановленные константы исторического сервера. Войти нужно повторно обычным способом; автоматический перезапуск/вход в клиенте этим обновлением не добавлялся.

При полном пропадании сети сервер сначала должен обнаружить обрыв: существующие TCP-проверки на хостинге могут занять примерно две минуты. Срок возврата отсчитывается после обнаружения. Одновременный вход в ещё живую сессию по-прежнему запрещён; [подробности обнаружения разрыва](CONNECTION_LIVENESS.md).

Бои сохраняются в памяти процесса. **Возврат в тот же бой после перезапуска сервера пока не реализован.** Штатная остановка завершает участие с сохранением накопленных результатов по правилам выхода. Аварийное завершение процесса не гарантирует сохранения ещё не записанных HP, опыта и состояния карты. Уже записанные операции с вещами остаются в базе.

Распределение целочисленного урона между пулями, округление клеточной линии M60/Minigun и формула брони остаются алгоритмами эмулятора. Для каждой пули её доля получается из случайного значения полного урона очереди; крит удваивает только эту долю. Итог по цели проходит действующую формулу брони `floor(raw × 100 / (100 + defence))`, минимум 1 для положительного попадания. Полное совпадение случайного распределения с утраченным оригинальным сервером не заявляется.

Гранатный разброс, огонь/ослепление/освещение, мины, специальные предметы, командные отметки и штатная передача вещей соседнему бойцу этим пакетом не реализованы. Они остаются отдельными задачами из аудита. Стартовые счета и экономический баланс игроков не изменялись.

## Проверка

- Автоматические тесты: **706 тестов — OK**, 228,777 секунды. [Полный журнал финальной проверки](reports/battle-core/tests.log), [дополнительные сценарии](tests/test_battle_core.py). Проверены частичные попадания и промахи очереди, влияние перка на крит, союзник и стена на линии пулемёта, откат при ошибке фиксации вещей, повторный вход, запрет действий до загрузки, истечение срока без подключённых игроков, завершение боя без связи, повторная выдача результата, восстановление шахты и изоляция чата.
- Оригинальная DLL: [результат](evidence/battle-core-native.json), [воспроизводимая проверка](tools/verify_battle_core_native.py). Выполнены оригинальные x86 обработчики чтения текста каналов 3/4 и записи `4B` для критов, промаха и нескольких целей. Выделение памяти, ANSI-строки и UI заменены стендами. Это проверка протокола, не интерфейса.
- Хостинг: [успешный сценарий](evidence/hosted-battle-core-qr24332bfc.json), [скрипт](tools/verify_hosted_battle_core.py). Пять новых независимых аккаунтов через публичный зашифрованный TCP: четыре в PvP 2×2 без ботов и один в городе. AK-47 израсходовал 5 патронов, нанёс 50 урона. После переподключения стрелок сохранил 7 ОД, позицию и инвентарь; получивший урон игрок вернулся с 950 HP из 1000. Командный канал остался изолированным. После выхода и нового городского входа расход патронов сохранился, на каждого участника записан ровно один результат боя.
- Для проверки созданы отдельные QA-персонажи с искусственными уровнем 10, HP 1000 и оружием. Эти данные не выдаются за проверку обычной прокачки. Первый прогон завершился ошибкой самого проверочного скрипта в последнем городском запросе инвентаря `2F`; сервер отклонил обрезанный пакет. Формат запроса исправлен, полный сценарий повторён успешно. Две группы QA-аккаунтов оставлены для воспроизводимого аудита.
- Метаданные двух фрагментов `village_house_02_v1.s` / `v2.s` приведены в соответствие с импортёром. Изменены только дополнительные хеши моделей; геометрия и прежние хеши сохранены. Это устраняет ранее зарегистрированный единственный FAIL полного набора.

Проверок мышью в оригинальном клиенте в этом пакете не выполнялось. Нужны визуальные подтверждения возврата сцены, таймера/признака отсутствия связи, текста вкладок и анимаций очередей/пулемёта.

После установки и двух сетевых прогонов проверены целостность SQLite и сохранность всех **1188 прежних строк в 42 таблицах**. Добавлены только 10 QA-аккаунтов и их игровые данные. Обе службы активны; на момент проверки `tio-server` не имел автоматических рестартов после установки (`NRestarts=0`).
