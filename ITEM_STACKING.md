# Стаки патронов и расходников

По запросу пользователя одинаковые патроны объединяются в одну запись с общим
количеством. Из медицинских предметов объединяются только Bandages9 и Candies34.
Патроны:3,4,5,6,7,12,13,14,15,36,37, включая дробь и гвозди Шахтёра.
Missile8, гранаты, остальные аптечки, ремонтные наборы и снаряжение не объединяются.

**24.10.2026:** обычные Upgrade Kit (шаблон30) тоже объединяются: в рюкзаке,
на личном складе и в клановом сейфе набор занимает одну ячейку, количество
показывает клиент и счётчик «три шеврона» внизу склада. Каталог клиента
`evidence/items_diagnostic.xml` получил `stackable=1`; он доставляется при входе
(shared config B9), обновлять клиент не нужно. Улучшение расходует один набор
из стака, ID стака сохраняется. Старые наборы объединяются при следующем входе
(`compact_saved_items`). Записи склада без привязки к городу (legacy) по-прежнему
не объединяются; такой набор присоединится к стаку после переноса в рюкзак и обратно.
Помеченные, арендованные и временные наборы остаются отдельными. Тесты:
`tests/test_upgrade_kit_stacking.py`.

**24.10.2026, ремкомплекты:** Repair Kit / Advanced / Super (17/18/19) тоже
объединяются, но только с одинаковым оставшимся ресурсом — на практике полные
наборы одного вида. Ремонт берёт из стака один набор; если ресурс израсходован
частично, этот набор отделяется в свою ячейку с новым ID, остальные остаются в
стаке. Ремонт сначала тратит уже начатые наборы, поэтому у каждого вида остаётся
не больше одного начатого набора. Счётчик очков ремонта не меняется. В бою новый
ID выдаёт общий счётчик ID матча и резервирует его в `item_sequences`. Тесты:
`tests/test_repair_kit_stacking.py`.

Для отделения частично потраченного ремкомплекта нужна свободная ячейка
рюкзака. Если её нет, ремонт отклоняется без расхода ресурса, ОД и новых ID.
Полный расход одного набора из стака не требует дополнительной ячейки.
Старый переполненный рюкзак можно уменьшать, но нельзя увеличивать ремонтом.

Количество измеряется в отдельных патронах/предметах:32 патрона плюс три
покупки по40 дают152. Цена покупки остаётся ценой пачки. Продажа части стака
рассчитывается пропорционально количеству в пачке с прежним коэффициентом65%.
Candies используют исходные power13/actionPoints1, расходуя один предмет.

Объединение выполняется в транзакции покупки обычного магазина/SC и переноса6B.
Каждый рюкзак и личный склад обрабатываются отдельно; вещи разных бойцов
или аккаунтов не смешиваются. Сохраняется ID первого подходящего предмета
назначения. Частичный перенос оставляет остаток источника; вместимость склада
проверяется после объединения. Поглощённые ID резервируются от повторной выдачи.

Для объединения должны совпадать все свойства, кроме ID и количества.
Надетые, помеченные и временные предметы не объединяются. При достижении
положительного предела знакового32-битного счётчика остаток хранится отдельно.
Вес единицы и суммарное количество не меняются.

При следующем входе `compact_saved_items` объединяет прежние сохранённые пачки
до отправки списков клиенту. Исходные изменённые снимки сохраняются в таблице
`item_stack_backups` той же транзакцией. Повторный вход ничего не дублирует.
Нельзя вызывать эту миграцию посреди боя или уже открытого клиентского списка.

В генерируемом клиентском XML включён stackable для Bandages/Candies и выключен
для Missile. Исходный items.cfg не меняется; правила подключены также к генератору
`build_item_fixture.py`. Старый каталог эмулятора распознаётся по точному SHA256
при восстановлении прерванного запуска, резервируется обычным механизмом.

Проверено:362 unit/integration tests;8 случаев исходного x86-кода — запись
stackable, разбор количества ItemList, выбор ветви диалога количества и
сериализация WarehouseList. Отрисовка и создание окон не эмулировались.
На отдельной копии сохранения склад сократился38→31 ячейка, рюкзак Шахтёра5→4;
полностью совпали количества и свойства по каждой локации, баланс сохранился.
Основная база пользователя не менялась. Полная визуальная проверка — после
перезапуска `python tools/run_reservation.py`.

Доказательства: `evidence/item_stacking_native.json`,
`evidence/item_stacking_saved_copy.json`, `data/stacking-tests.log`.
