# Выживание: подбор реального игрока

Обновление 23.09.2026. Общая очередь доступна на сервере с `multi_account = true`.
Одиночный диагностический запуск теперь тоже не подставляет бота, но другого подключения в нём нет.
Для применения изменений требуется перезапуск сервера; удалённый сервер не обновлялся.

Источник правил: https://ti.ggeek.ru/files/TIO_manual.pdf, печатная страница 15,
раздел «Выживание» (индексированный текст проверен 23.09.2026).
Подбираются реальные заявки одного диапазона: 1–3, 4–6, 7–10, 11–15, 16–20.
Предпочтение большему общему числу бойцов, затем более ранней заявке.
В бой идут первые min(N, M) бойцов; сохранённый состав не меняется.
Текущее ограничение — Reservation, без подбора между другими городами.
При отсутствии соперника ожидание не ограничено таймером и не запускает бота.

Клиентский протокол сохранён по ARENA.md и original native evidence:
- BA03/category=0/count → BA0B с собственным ID и выбранными бойцами, ready=1.
- BA07/boolean → BA08 с ID поиска, собственным ID и готовностью; 0 приостанавливает подбор.
- BA05/ownID/kick=0 → пустой BA0B с ID=0xffffffff, удаление заявки.
- После подбора оба клиента получают 6C/25/35, видимые 3B, способности,
  инвентари, известные мины и 41. Начало ходов только после 36 от обоих.

Бой использует существующий общий серверный battlefield, уникальные сетевые ID,
проверку прав на действия и сохранение результата отдельно для каждого аккаунта.
Отмена и отключение удаляют заявку под общим lock. Неудачная подготовка сцены
не потребляет заявки. Отключение в бою обрабатывается общим боевым сервисом.

Автопроверки: test_matchmaking.py, test_survival_service.py,
test_shared_team_arena.py. Проверка двумя открытыми игровыми клиентами не выполнялась.

Итог проверки: 576 unit/integration tests PASS; original native builders/callbacks 9 PASS, BA08 consumer 4 PASS. Лог: data/survival-multiplayer-test-results.txt.
