## Что найдено в установленном клиенте

`C:\Program Files (x86)\TIOnline\base\autoexec.cfg`:

```text
orange_addr 139.162.160.97
orange_port 28512
```

В `base/config.cfg` также есть `orange_port 28512`; в `base/serverlist.cfg` —
`<New Mexico> gameserver`, то есть название сервера, а не адрес подключения.
В silver.dll обнаружены строки login.ini и Software\LVI\TotalInfluence, но
рабочие параметры адреса через registry/command line не подтверждены. Не нужно
угадывать ключи реестра или патчить исполняемые файлы.

## Замена адреса (Windows, закрытый клиент)

1. Сохранить резервные копии `base/autoexec.cfg` и `base/config.cfg` вне каталога
   клиента. Для записи в Program Files могут понадобиться права администратора.
2. В autoexec.cfg заменить только значение orange_addr на публичный IPv4 VPS;
   orange_port оставить 28512 либо поставить выбранный game_port.
3. В config.cfg синхронизировать orange_port; если там есть orange_addr,
   синхронизировать и его. Сохранить исходную кодировку файлов.
4. На сервере в `/etc/tio-server/server.toml` поставить тот же IPv4 в
   advertised_address, затем `sudo systemctl restart tio-server`.
   Сервер отдаёт его в пакете 06: второе TCP-подключение иначе уйдёт по старому IP.
5. Проверить сеть с компьютера:

```powershell
Test-NetConnection PUBLIC_IPV4 -Port 28512
cd C:\TIO-emulator
python deploy/check_connection.py --host PUBLIC_IPV4 --port 28512
```

В командах заменить PUBLIC_IPV4 фактическим адресом VPS. Успех второй команды
означает только получение настоящего TIO transport challenge, а не вход в город.

## Ограничения диагностического режима и альтернативного запуска

`python tools/run_reservation.py` запускает ЛОКАЛЬНЫЙ сервер. Его
`capture_loaded_orange.py` вызывает connect с 127.0.0.1 и блокирует другие
соединения через Winsock-hook. Изменение CFG не перенаправляет этот путь на VPS.
Запускатель намеренно не изменён по ограничению текущей задачи.

Подтверждённый штатный путь — запуск установленного `ti.exe` из его каталога
после настройки CFG (например, ярлыком с этим working directory). Ограничения:

- режим по умолчанию принимает `probe_user` / `probe_password`; в новом режиме
  действуют только явно созданные учётные данные;
- создание поддерживает только имя ProbeNew и нулевой профиль, выбор — slot 1;
- предыдущий рабочий путь использовал исправление загрузки orange.dll в памяти,
  native callbacks входа/выбора и дополнительные compatibility hooks;
- штатные server settings ещё не полностью восстановлены: часть значений
  лечения/улучшения передавалась через клиентские hooks.

Существующее сохранение лучше перенести целиком: тогда диагностическое создание
не понадобится. Если клиент не входит,
сопоставить его log.txt с `journalctl -u tio-server -f`. Не выдавать `TcpTestSucceeded`
за проверку игры. Проверку одновременного входа проводите по MULTIPLAYER.md.

При смене IPv4 VPS меняются только CFG клиента, advertised_address и правила
firewall при необходимости. Python source не меняется. Для отката восстановить
копии CFG; существующий локальный запускатель продолжает работать как раньше.
# Опциональный режим нескольких аккаунтов

См. MULTIPLAYER.md: адрес клиента и начальный порт 28512 остаются прежними;
порт игровой сессии 28513 приходит в списке серверов. Используйте пароль,
назначенный через `python -m server.accounts`, а не диагностический пароль.
