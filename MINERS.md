# Шахтёр и вход в шахту

Реализован найм в отдельной локации Miner's Town (ID9). На карте вход
восстановлен по исходному base/towns.cfg: северо-восточнее Reservation,
центр(-77,-447), границы(-90,-460)—(-64,-434), зона26×26.
Для проверки закройте игру и прежний эмулятор, затем запустите:

```powershell
python tools/run_reservation.py
```

Откройте карту, нажмите на город шахтёров и дождитесь прибытия, затем откройте найм. Шахтёр стоит 3500 кредитов.
Покупка сохраняется, повторный найм создаёт нового бойца. В Reservation
предлагаются прежние люди и собаки. Возврат — через карту, щелчком по Reservation.
Положение и маршрут сохраняются при перезаходе; время пути продолжается офлайн.
Имя нового шахтёра — Shrek. Старые имена эмулятора «Шахтёр»/Freak Miner
заменяются при запуске; собственные имена игрока сохраняются.
Инвентарь, идентификаторы и деньги при переименовании сохраняются. Для обычного Survival
нужно вернуться в Reservation.

## Подтверждённые данные

[Руководство Total Influence, стр.43 и FAQ стр.105](https://ti.ggeek.ru/files/TIO_manual.pdf):
98 здоровья, 14 ОД, обзор8, грузоподъёмность1000, найм3500 кредитов;
у шахтёров отдельное оружие и броня.

Клиент `base/mobs.udf`: resource6, class=human (формат экипировки),
freakminer_skeleton, базовые модели65511/65512, оружие без экипировки337.
Модель, анимации и фон loc_miners присутствуют в клиенте.
`base/towns.cfg`: Miner's Town ID9, арена выключена. Оригинальный загрузчик
silver.dll по ID9 выставляет IsMinersTown (9EADF4–9EAE00).

Из исходных items.cfg/XML также подключены проверки совместимости снаряжения:
шахтёр принимает Freak, обычные люди/собаки его не принимают. Уровень для
брони берётся из клиентского каталога. Базовые удары без оружия используют337,
а не человеческие кулаки300. Параметры шахтёра передаются и в боевую сцену.

## Локальные правила и границы

- Движение по карте постепенное, с исходным сглаживанием клиента. Можно
  выбирать произвольные точки и менять маршрут в пути. В бою и поиске боя
  переход запрещён; вне города его услуги и найм недоступны.
- Скорость увеличена по запросу пользователя с 3 до 6 единиц карты в секунду.
  Историческая скорость сервера не установлена. Между центрами городов около25с.
- Координаты ID9 восстановлены из клиента. Руководство на стр.12 подтверждает
  назначение города, но не содержит числовых координат.
- Уровень нового бойца1; стартовые владения оружием используют прежнюю
  временную политику эмулятора. Это не восстановленные исходные значения.
- Способности шахтёра добавлены следующим этапом: см. MINER_ABILITIES.md.
  Добыча кристаллов, шахтные бои и отдельные эффекты шахтёрских предметов
  пока не реализованы. Обычный Survival поддерживает
  базовые атаки шахтёра, включая его штатное оружие.
- Иконки/модель/меню после реального нажатия ещё требуют проверки пользователем.
  Автоматические проверки не заменяют тест в игровом окне.

## Протокол и проверки

- Клиент9EE7F6 →889E5C →6517F8: запрос1B + два signed i32 (x,y).
- Ответ1D: characterID, currentXYZ, destinationXYZ, bool мгновенного перемещения.
  Оригинальный88B130 при false сохраняет дробную позицию отрисовки.
- Ответ1E завершает движение без сброса сглаживания. F0/97 закрывает город.
- Скорость из MyCharInfo1A u16 поступает в character+8; шаг9EDD18 использует
  скорость и время, отрисовка9EDF92 сглаживает координаты.
- map_journeys хранит начало, цель и абсолютное время прибытия; при входе
  восстанавливается актуальное положение либо завершается истёкший маршрут.
- C82D + F0/98 + F0/117 обновляют данные локации и открывают её.
- Найм61/62/63/66 использует существующий атомарный HireStore. Место найма
  проверяется по серверной БД в той же транзакции, что и предложение/списание.

`python -m unittest discover -s tests -q`: 332 теста PASS.
`python tools/verify_miner_native.py`: PASS; оригинальные writer1B, reader1D,
каталог62 и PetInfo66. UI и создание объектов в последних двух пробах
используют явно обозначенные заглушки. Данные: evidence/miner_native.json.
`python tools/verify_map_motion_native.py`: PASS; исходные1D/1E, шаг движения,
арифметика сглаживания и смена текущего города F0/97. UI-вызовы изолированы.
Данные: evidence/map_motion_native.json и evidence/map_motion_original.asm.
Рабочая база игрока автоматическими проверками не изменялась.

Для уже открытой старой сессии предусмотрено распознавание точного SHA256
двух прежних вариантов zones.xml (три города и девять с перенесённой шахтой). При следующем запуске он копируется в session-backups
перед заменой; посторонние каталоги по-прежнему не удаляются.
