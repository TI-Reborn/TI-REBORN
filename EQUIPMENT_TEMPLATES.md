# Шаблоны экипировки

Восстановлена обработка семейства C5 в `tools/loopback_exchange.py`.
Шаблоны сохраняются в SQLite, таблица `equipment_templates`, отдельно для
каждой учётной записи. Перезапуск не удаляет комплекты.

## Проверка в игре

1. Перезапустить игру и эмулятор: `python tools/run_reservation.py`.
2. Открыть склад и редактор через «Экипировка» под моделью бойца.
3. Импортировать снаряжение выбранного бойца либо выбрать вещи вручную.
4. Указать тип и уровень бойца, сохранить новый шаблон с именем.
5. Перенести его вещи на личный склад и применить шаблон к совместимому бойцу.
6. Проверить изменение, «Обновить текущий», отключение и удаление шаблона,
   затем сохранение списка после повторного входа.

## Поведение

- Основное и второе оружие, головной убор, корпус, ноги, боеприпасы и рюкзак.
- Импорт в редактор выполняет оригинальный клиент; сервер сохраняет результат.
  Команда «Обновить текущий» переснимает комплект с указанного бойца.
- Экипировка ссылается на конкретные экземпляры, припасы — на тип, количество
  и усиление урона, как в исходящем пакете клиента.
- Источники при применении: вещи получателя и личный склад. Другие бойцы
  автоматически не раздеваются. Отсутствующие вещи не создаются.
- Уровень, тип бойца, ограничения оружия/брони и пересекающиеся слоты проверяет
  тот же код, что обычное надевание. Импланты вне семи полей этого редактора
  сохраняются надетыми.
- «Удалить лишнее» переносит лишние вещи на личный склад. Без этой настройки
  они остаются в рюкзаке. Количество припасов в таком случае — минимальный запас.
- Перенос, разделение стопок и изменение активного шаблона — одна транзакция.
  Нехватка вещи/количества/места или ошибка записи отменяет всю операцию.
- Заточка, прочность, метки и срок аренды сохраняются. Правила объединения
  стопок прежние: гранаты и ракеты не объединяются.
- В бою, заявке и движении по глобальной карте изменения запрещены.
- Локальные защитные пределы: 200 шаблонов на аккаунт, 128 UTF-16 единиц в имени,
  до 100000 единиц припаса в одной строке. Они не выдаются за исторические правила.

## Ограничения обслуживания

В клиенте восстановлены значения настройки: 0 — выключено; 1 — «Автопочинка»;
2 — «Починка»; 3 — «Автозакупка» (`92bfec`, строки m1036/m1038/m1037).
Они сохраняются и возвращаются в редактор без изменения. Финансовые операции
ремонта и автоматической покупки пока не подключены: для них здесь нет
подтверждённой серверной цены/правил. Если для применения нужен такой ремонт
или докупка, сервер явно отказывает, сохраняя вещи и баланс. Для обычного
комплекта используйте выключенное обслуживание и заранее купленные припасы.
Автоматическое применение после каждого боя также не включено.

## Оригинальный протокол

Исследован `silver.dll`, SHA256
`a73396748ea5c3530157db53592a9f3e04744592c3711f38d40d4877b785de11`.

| Направление | Команда | Оригинальная функция |
|---|---|---|
| C2S | C5 01: список | 92ec28 |
| C2S | C5 03, действие 0: просмотр, ID шаблона и бойца | 92ec9c |
| C2S | C5 03, 1/3: изменение/создание | 92ee38 |
| C2S | C5 03, 2: удаление | 92ec5c |
| C2S | C5 03, 4: применение; ID 0 отключает | 92edec |
| C2S | C5 03, 5: обновление с текущего бойца | 92eda0, вызов 92d7cd |
| S2C | C5 02: список | 92f4b8, запись 92eb48 |
| S2C | C5 04: отключение у бойца | 92f430 |
| S2C | C5 06: выбранный/созданный ID | 92f568 |
| S2C | C5 08: содержимое | 646260/646328; элемент 645b58/645bec |

Имена в списке и запросе сохранения — UTF-16LE с нулевым терминатором.
В C5 08 имя имеет длину u16 в байтах и кодировку UTF-8. Первые семь элементов
обязательны даже для пустого комплекта: оружие, патроны, второе оружие,
патроны, голова, корпус, ноги. Затем идут припасы рюкзака. Элемент C5 08:
u32 objectId/itemId/count; i8 service/enhancement; u8 damage; u16 durability/max.

PetInfo66 использует поле `8c4f74` для ID активного шаблона и условную строку
UTF-16Z `8c4f9c`, когда ID не равен нулю. Кодек теперь поддерживает обе ветви.
В базу записывается базовое состояние бойца, клиенту отправляются текущие
производные характеристики с учётом навыков и снаряжения.

## Проверки

`python tools/verify_equipment_templates_native.py` выполняет исходные x86
функции: семь вариантов отправки (включая полный пакет сохранения), два списка
и два просмотра. Проверяет полное чтение, значения полей, кириллицу и флаг
загрузки списка. UI, выделение памяти и операции управляемых строк изолированы;
это проверка протокола, не визуального результата в игре.
Результаты: `evidence/equipment_templates_native.json`.

`tests/test_equipment_templates.py` проверяет SQLite, повторное применение,
перенос/разделение, сохранность метаданных, изоляцию аккаунтов/бойцов, профили
людей/собак/шахтёров, откаты и ответ реального обработчика транспорта.
Все проверки используют временные базы; данные игрового аккаунта не менялись.
